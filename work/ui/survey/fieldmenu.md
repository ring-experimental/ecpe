# 필드 메뉴 조사 (에픽크로니클PE)

주소는 모두 `client.bin` 파일 오프셋(게스트 = +0x100000). "검증"은 memdump/calltree로 확인한 것, "정적"은 역어셈블만으로 읽은 것.

## 0. 공통 구조

### 0.1 뿌리에서 메뉴 객체까지 (memdump로 검증)

| 단계 | 식 | 이번 실행 값 |
|---|---|---|
| GOT 기준 | 파일 `0x4e624` (게스트 `0x14e624`). PIC 코드의 `sl` 값 | |
| 앱 전역 변수 주소 | `*(0x14e624 + 0x294)` | `0x14ee34` |
| 앱 객체 | `*gvar` | `0x400020` |
| 게임 객체 | `app + 0x48` | `0x42bb6c` |
| 메뉴 객체 | `game + 0x1d4` | `0x42d91c` |
| 현재 화면 객체 | `menu + 0x24 + 4*menu[+0x18]` | |

- 레지스터로 잡기: 필드 틱 `0x109b8`의 r0 = 게임 객체, 메뉴 분배 `0x2faa4`/키 분배 `0x2fa60`의 r0 = 메뉴 객체, 각 화면 그리기(vtable+4)의 r0 = 화면 객체, r1 = gfx(`game+8`). 화면 키 처리(vtable+8)는 r0 = 화면 객체, r1 = 키 이벤트(`+0` u16 코드, `+2` u16 1=누름, `+0xc` 유효). 코드 변환은 `0x61d4`.
- 게임 키 코드(`0x6584`: WIPI 키 + 0x20): 위 `0x1f`, 아래 `0x1e`, 왼 `0x1d`, 오른 `0x1c`, OK `0x1b`(RSK도 OK로), LSK `0x1a`, CLEAR `0x10`, 숫자 `'0'..'9'` → `0x50..0x59`, `*` → `0x4a`, `#` → `0x43`. 대부분의 화면이 숫자 2/4/5/6/8을 방향/OK 대용으로 받는다.
- 메뉴 열기: `0xcea8(game, 첫 화면, 모드, 캐릭터)` → 게임 상태 `game+0xc = 0xe`, `menu+0x18 = 첫 화면`, `menu+0x1c = 모드`, 생성 `0x2f924`, `0x2faf4(menu, 캐릭터)`, `0x2fb00(menu, s0)`. 호출처:
  - `0x1054c`: `cea8(game, 0, 1, 0)` — 필드에서 CLEAR(일반 메뉴)
  - `0x104e0`: `cea8(game, 7, 2, 1, 2)` — 옵션을 모드 2로 바로 연다(바탕 창 없음)
  - `0x10740`(상태 복원): 하위 상태 0 → `cea8(game,0,1,0)`, 7 → `cea8(game,7,3,..,1)`, 8 → `cea8(game,8,1,0)` + `0x2fa94(menu, game[+0x55c], game[+0x560])`
  - `0x1cf38`: `cea8(game, 4, 1, 캐릭터)` — 스테이터스를 바로 연다
- 메뉴 객체 필드(검증): `+0x00` game, `+0x04..+0x17` 스프라이트 래퍼(메뉴 스프라이트, `+0x14` = 스프라이트 = 리소스 5), `+0x18` 화면 번호, `+0x1c` 모드(1 필드, 2/3 옵션 직행; 2면 바탕 창 생략), `+0x20` 화면 객체 풀(0x28c 바이트, `0x6870`로 할당, `0xb20c`로 배치), `+0x24..+0x44` 화면 객체 9개, `+0x60` 닫기 요청(1이면 메뉴 종료), `+0x64`/`+0x68` 창 x/y (= 화면폭/2-60, 화면높이/2-73; 512x320에서 196,87), `+0x6c`/`+0x70..` 비밀 코드 버퍼, `+0x78` 화면 폭.
- 분배 `0x2faa4`: `menu+0x60`이 0일 때만 그린다. `+0x1c != 2`면 먼저 바탕 창 `0x1415c(x, y, 120, 146, 0x40252200)`. 화면 7(옵션)이면서 `menu[+0x40]+0xc == 3`이면 아무것도 안 그린다. 이어서 화면 vtable+4.
- 키 분배 `0x2fa60`: 화면 번호가 0이 아니고 키가 `#`(0x43)면 메뉴 전체를 닫는다(`+0x60=1`). 아니면 화면 vtable+8.
- 그리기 호출 경로(공통): `0x6604 > 0x6720 > 0xbba0 > 0x44f1c > 0x109b8 > 0x2faa4 > 0x44f1c > <화면 그리기>`.

- 색 값은 `0xBBGGRR00`이다(픽셀로 검증: `0x40252200` → #222540, `0xa3d9f000` → #f0d9a3).

## 1. 메인 메뉴(화면 0)

- 이름: 위 띠에 탭 이름(아이템/스킬/장비/스테이터스/퀘스트/전투파티/옵션) — 그림 프레임이다(글 아님).
- 가기: 필드에서 `clear`. 탭 이동 `right`/`left`(또는 6/4), 7개 순환.
- 스크린숏: `메인메뉴.png`, `메인메뉴_탭7종.png`(탭 0~6과 한 바퀴 뒤 아이템), `메인메뉴_캐릭터선택.png`, `치트_토스트.png`.
- 그리기 `0x310e8` = `0x31238`(머리띠) → `0x31398`(캐릭터 카드 3칸) → 띠 채움 `0x1415c(x0, y0+0x5f, 120, 0x16, 0x5c303000)` → `0x31474`(금액) → `0x314d0`(시간) → `0x31508`(장소) → `0x30884`(키 안내 종류 0) → 치트 알림(`+0x50`).
- 키 `0x30ef0`(점프 표 정적 해독):

| 키 | 보통(`+0x20=0`) | 캐릭터 선택(`+0x20=1`) |
|---|---|---|
| CLEAR, LSK | 메뉴 닫기(`menu+0x60=1`) | 선택 취소(`+0x20=0`) |
| 오른/6 | 탭+1(6 다음 0) | 커서 오른쪽(`0x30dc0(+0x28, 3, 0)`) |
| 왼/4 | 탭-1(0 앞 6) | 커서 왼쪽 |
| OK/5 | 탭 0 → 화면 1(아이템 목록 초기화 `0x30e38`, 텍스트 상자 `0x3b40`), 탭 4 → `0x337f0` 후 화면 5, 탭 5 → `0x34e84` 후 화면 6, 탭 6 → 화면 7, 탭 1~3 → `+0x20=1` | 탭 1~3 → `menu+0x18 = 탭+1`, `0x2faf4(menu, +0x2c)`로 대상 캐릭터 전달. 스테이터스(4)면 캐릭터 `+0x194`가 0일 때 `0x2fb00(menu,-1)`, 아니면 `0x2fb00(menu,0)` |
| `# * 1 3 7 9` | 비밀 코드 버퍼에 쌓음 | |

- 비밀 코드: `9 9 * 9 * #`(버퍼 `"YYJYJC"`, `0x40778` 비교) → `game+0x4bc` 비트 0x20을 뒤집고 화면 가운데에 빨간 띠(`0x30078`, 높이 20, 색 `0x44261c00`/`0x2600b100`) + 글 "Cheat Enabled.."/"Cheat Disabled.."(`0x3a1c`, x=4)를 약 16프레임 보인다. 검증(nctl `9 9 star 9 star hash`, memdump로 비트 확인 뒤 다시 꺼 둠). 이 비트가 무엇을 여는지는 확인 안 함.
- 화면 0 객체 필드(검증):

| 오프셋 | 뜻 |
|---|---|
| +0x0c | 탭 번호 0~6 |
| +0x20 | 1이면 캐릭터 선택 단계 |
| +0x24 | 화살표 깜빡임(매 그리기마다 0/1 토글, 좌우 화살표가 1px 안팎으로 움직임) |
| +0x28 | 목록 상태(`0x30db4` 초기화, `0x30dc0` 이동): +0x28 맨 위 파티 번호, +0x2c 선택한 파티 번호, +0x30 보이는 칸 안 커서(0~2) |
| +0x4c | 메뉴(목록 도우미가 `[+0x4c]`=game을 씀) |
| +0x50 | 알림 상태: 낮은 바이트 종류(1/4/8), 그 위 프레임 수(0x10 넘으면 끝) |

### 1.2 캐릭터 카드 `0x31398` / `0x30a38`

- 칸 3개: `0x2ff80(40*i, 0x17, 40, 62)`, i=0..2.
- 파티 목록: `game+0x1c0` = 파티 객체, `파티+0x84+4*k`(k=0..4) = 캐릭터 객체(0이면 빈 칸), `파티+0xa8` = 돈. `+0x28`부터 최대 3명.

## 공통(스킬·장비 화면이 같이 쓰는 것)

- 좌표는 모두 메뉴 창 원점 기준: `X = menu+0x64`, `Y = menu+0x68` (폭 512에서 196,87). 창 크기 120×146(분배 `0x2faa4`가 `0x1415c(X,Y,120,146,0x40252200)`로 바탕을 먼저 칠함).
- 화면 객체 공통 머리(기본 생성자 `0x2ff2c`→`0x2ff5c`): `+0` vtable, `+4` menu, `+8` = menu+4(메뉴 스프라이트 래퍼), `+0xc` 캐릭터 슬롯 번호(0~4), `+0x10` 하위 상태, `+0x18` 메시지 표시 프레임 수(20, 게임 플래그 `[game+0x14c]&0x80`이면 7).
- 캐릭터: `party = [game+0x1c0]`, `char = [party+0x84+4*slot]`(슬롯 0~4, 0이면 빈 자리). 메인 메뉴에서 캐릭터 선택 후 `0x2faf4(menu, idx)`가 `screen+0xc`를 정한다.
- 좌/우로 캐릭터 바꾸기 `0x3023c(screen, dir)`: 비어 있지 않은 다음/이전 슬롯(0~4 순환).
- CLEAR로 메인 복귀 `0x2fb0c(menu, n)`: `menu+0x18=0`, 메인 `+0xc = n-1`(탭 유지). 하위 화면 어디서든 `#`이면 `0x2fa60`이 `menu+0x60=1`로 메뉴 전체를 닫는다.
- 그리기 도구: 테두리 상자 `0x2ff80(x,y,w,h)`(4겹 외곽 `0x14184` 색 40252200/a3d9f000/9c8a9400/40150d00 + 안쪽 `0x1415c` 5c303000), 칸 상자 `0x37a24(x,y,w,h,외곽색,안색)`(두 색이 같으면 선택색 ffad9900/e76c5600), 가로 구분선 `0x2fffc`(3줄 a3d9f000/9c8a9400/40150d00), 글 상자 `0x14240(x,y,w,h,str,flags)`(→`0x3bf0`→`0x3c0c`, flags 0x120=한 줄, 4=줄바꿈, 0x22=가운데), 글자색 `0x3f14(font, RGBA)`. 숫자 `0x37a78(x,y,값,색,정렬,0)`: 메뉴 스프라이트 프레임 0x27(5px 숫자 칸)을 `0x6104`로 그림.
- 스프라이트 호출 `0x60dc(wrapper, x, y, frame, flip, clip*)`. 래퍼 둘: **M** = `menu+4`(시트 포인터 `menu+0x14`, 이 실행 0x437380), **G** = `game+0x4c0`(이 실행 0x42c02c). `0x56ec(sheet, frame, x, y, ox, oy, flags)`는 시트 직접.
- 공통 조각
  - 초상 상자 `0x300a0`: 상자(X,Y,32,31), 클립(X+4,Y+4,24,23) 안에 `0x56ec(M시트, frame=0x12fe8(game,char[4],0), X+4, Y+4, dx, dy)`(dx/dy는 GOT+0x438/+0x43c 9바이트 표, 반환 0x43이면 표 인덱스 8).
  - 스킬 머리 `0x34a08`(스킬 화면, 상태 4 제외): 상자(X+31,Y,89,31); 이름표 `0x2fe7c`(G 프레임 0x24+char[5] at X+42,Y+4); "LV" M#0x11 (X+39,Y+12), 레벨 `stats+0x18`(byte) at X+54 흰색; "HP" G#0x2d (X+63,Y+12), HP `stats+0`/최대 `stats+4` at X+88/X+99 색 54e0ff00, "/" M#0x29(X+93,Y+13); "MP" G#0x2e (X+63,Y+19), MP `stats+8`/최대 `char+0xf4` 색 fffcab00, "/" (X+93,Y+20). 상태 0일 때만 좌우 화살표 M#0x1d (X+110,Y+4)와 뒤집힘(X+36,Y+4). `stats = [char+0x64]`.
