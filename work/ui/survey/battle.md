# 전투 UI 조사

주소는 `client.bin` 파일 오프셋(게스트 +0x100000). 색은 `0xBBGGRR00`(예: `0x54e0ff00` = RGB(255,224,84) 노랑).
스크린샷은 `shots/battle/`(512×320, 따로 적은 것 빼고 액티브 모드). 실행 폴더 `work/ui/run/battle*`, 보존본 `work/ui/run/battle_keep/`(메모리 덤프 `m_active.bin`(액티브), `m_turn.bin`(턴), `m_240.bin`(폭 240), 호출 나무 `ct_*.txt`, 패배 프레임 기록 `lose/`).

## 0. 요약

- 원작 전투는 **실시간 ATB**(옵션 "전투: 액티브/턴")다. 아군 ATB가 차면 왼쪽 아래에 명령 메뉴가 뜬다. 액티브 모드에서는 메뉴를 열어 둔 동안에도 적이 행동한다.
- 화면 UI는 사실상 **아래 띠 하나(높이 48)** + 위에 겹쳐 뜨는 작은 상자들(이름표, 메시지, 결과)이다. 턴 순서 표시, 상태이상 아이콘, 콤보 패널, 보스 소개 띠, 전투 튜토리얼 팝업은 그리기 경로에 **없다**(정적 열거로 확인).
- 사용자 저장 사본(현재 `fc8ff…`, 성 안이라 인카운트 없음) 대신 `work/shots/b512/save`(이전 저장 사본 `4c496…`, Arc Lv 초반 1인 파티)로 전투했다. 이 저장에는 스킬·필살기·조합기·두 번째 동료가 없어 그 목록 창은 **정적 분석만** 했다.
- 턴 모드 저장 사본: b512 저장 + `gopt.sav` 첫 워드 `0x80000221`(bit0=턴).

## 1. 뿌리와 객체

```
GOT+0xf0 (0x14e714) → 0x14edd4 (전역) → app(0x400014) ; [app+0x54] = game   (덤프로 확인)
game+0x1c8 = battle (B)      game+0x8 = gfx(+0xdc 클립 x,y,w,h)    game+0x14c bit0 = 전투 턴 모드(1)/액티브(0)
game+0x160 = 큰 글자 배치 플래그(관측값 2, 240/512/640 모두 2. 0이면 작은 배치) — 정체 미확인
game+0x1d4(+4) = 공용 UI 스프라이트 시트(결과 창 동전/EXP/LVUP 등)   game+0x4c0 = 적 패널용 시트(미도달)
game+0x568 = 화면(보기) 사각형 — 전투 메시지 상자가 이 사각형 기준
```
장면 틱 `0x109f0`: `0x1c4cc(B, 키)`(갱신) → `0x1bcd4(B, gfx)`(그리기).

### 전투 객체 B (크기 ≥0x1d0, 생성 `0x1b1d0`)
| off | 뜻 |
|---|---|
| +0x00 | game |
| +0x04 | 아군 진영 P, +0x08 적 진영 E |
| +0x0c | 현재 행동자(행동 객체, `+4` 플래그), +0x10 다음 행동자 |
| +0x28 | 플래그. bit 0x20 = '7' 키를 누르고 있음(적 이름표), 0x10/0x8 대상 쪽 |
| +0x2c | 대상 인덱스(선택 중인 대상 번호) |
| **+0x30** | **상태 번호(0~0x2a)** |
| +0x34 | 하위 단계/결과 쪽 번호(결과 화면 0=골드·EXP, 1=스킬획득, 2=드롭) |
| +0x38 | 전환 카운터 |
| +0x50,+0x54 | 스킬표/아이템표(`0x23f50`/`0x240dc` 조회, `0x24090` 이름, `0x24100` 아이콘) |
| +0x58 | 상태 패널 SP(0x14 B, 생성 `0x1e0a8`) |
| +0x5c | 명령 메뉴 CM(0xd8 B, 생성 `0x1e4d4`) |
| +0x60 | 적 정보 패널 EP(0x18 B, `0x1ee00`) |
| +0x64 | 메시지 상자 MSG(0x70 B, `0x230f0`/`0x2320c`, 필드 대사 상자와 같은 클래스) |
| +0x6c | 맵 그리기 객체(배경, 이미 `restored/battle.c`) |
| +0xb8 | 갱신 격자 |
| +0x120 | 적 이름표 NM(0x14 B, `0x1dfbc`) |
| +0x160 | 깜빡임 토글(매 프레임 0/1, 커서 깜빡임) |
| +0x174 | 대상 선택 중(커서 그리기 조건) |
| +0x198 | 목록 모드(1=아이템/조합 창 열림, 2=사용 확인 중) |
| +0x19c | 조합(Combi) 가능(동료 있음) — 0이면 Combi 회색 |
| +0x1c0 | 아래 패널 높이 = 48 (덤프 확인) |

### 진영 P/E
- `+0x0c` 인원, 아군 `P+0x98+4i` 멤버, 적 `E+0x3d0+4i` 적. `P+0x1c` 현재 ATB 찬 멤버(+0x54 뺀 것).
- 결과 값(승리 때 채움, 시작 때 0 — 턴 덤프로 확인): `P+0x30` 얻은 EXP, `P+0x34` 골드, `P+0x38` 드롭 개수(u8), `P+0x39..` 드롭 아이템 id(u8). `P+0x7c`=1 도망 요청.

### 멤버 M (vtable 0x14d980, `M+0x54` 행동 하위 객체 vtable 0x14d9bc)
| off | 뜻 |
|---|---|
| M+0x64 → S | S+0 HP, +4 최대 HP, +8 MP, +0xc ATB 최대, +0x10 ATB 값(≥최대면 가득) — 덤프로 확인(88/104, 25/25) |
| M+0xf4 | 최대 MP(25) |
| M+0xf8 / +0xfc | MG(필살 게이지) 현재/최대(315/315 가득, 208/315) |
| M+0x58 | 상태 플래그(0x8000 전투불능, 0x40 ATB 준비, 0x800 행동 중 …) |
| M+0x5c bit29 | 적 정보 패널 사용 가능(장비/능력, 미확인) |
| M+0x13d+k | 단축 스킬 3/6/9 슬롯(u8 스킬 id) |
| M+0x154 | 레벨업 함(결과 화면 LVUP 표시), M+0x158 새 스킬 얻음 |
| M+0x1a0 | '1' 키 토글: 적 정보 패널 보이기 |
| 이름 | `0xca2c(game, M, …)`가 스프라이트 글꼴로 그림("Arc") |

### 적 X (vtable 0x14d81c)
`X+4` 플래그(0x10000=숨김/죽음), `X+0x10` 스탯(+0 HP, +4 최대 HP), `X+0x28/+0x2c` 화면 x,y(덤프: 136,135 / 68,230 @512), 이름은 vtable+0x14가 돌려주는 글. `S+0x21..` 니블 4개(속성/저항 추정, 적 패널에서 막대로).

## 2. 상태 기계 (B+0x30)

갱신 `0x1c4cc`의 표(0x48504, 43칸)와 보조 표(0x485b0, 6~16).

| 상태 | 갱신 | 뜻(추정 포함) |
|---|---|---|
| 0,1,6~8,10,12,14,16~21,27~41 | 기본: 현재 행동자 vtable+0xc, `0x19764`(양 진영 ATB) | 진행 중(ATB 흐름, 연출) |
| 2 | `0x1c7ec` | 전투 시작, 선공 결정 → 3 |
| 3 | `0x1c878` | ATB 진행 |
| 4 | `0x1c8a8` | 명령 입력/행동 실행(MP·MG 부족 메시지, 대상 확정) |
| 5,6 | `0x1d140` → 9/10 | 행동 연출 대기 |
| 9,10 | `0x1d16c` → 5/6 | 다음 행동자 고르기 |
| 11,12 | `0x1d2b4`/`0x1d2cc` | 행동 끝 처리 |
| 13,14 | `0x1d2f8` | 대기 |
| 15,16 | `0x1d330`(→2/4) | 승패 검사 `0x1d6d0`: 아군 전멸 → 0x19, 적 전멸 → 0x16 |
| 0x16 (22) | `0x1cb88` → 0x17 | 승리 계산(EXP·골드·드롭, 레벨업) |
| 0x17 (23) | `0x1cf38` | **결과 화면**(그리기 `0x1c1ac`, 키로 B+0x34 쪽 넘김, 끝나면 필드) |
| 0x18 (24) | 없음 | 대기 |
| 0x19 (25) | `0x1c654` | **패배**: 페이드 아웃 → 타이틀(게임 오버 창 없음) |
| 0x1a (26) | `0x1c780` | 전투 나가기(도망 성공 등) → 필드 |
| 0x2a (42) | 없음 | 그리기·갱신 생략(전환) |

공통: 매 프레임 `0x1c49c`(현재 행동자 ATB 준비면 `0x177bc` → CM 키 처리 `0x1e594`), 메시지 상자 `0x23408`.
'7' 키(내부 코드 0x10057 길게)면 B+0x28 |= 0x20.

## 3. 그리기 `0x1bcd4` 순서

1. 맵 배경 `0x3892c`(B+0x6c), 격자 표시(상태 5,6,0x17,0x19는 전부 다시 그림 `0x207c8`).
2. 적 `E+0x3d0[i]`: vtable+0x30 → 위치 `0x1bc40` → 스프라이트 `0x15724`. 대상 커서: vtable+0x40 = `0x196c0`(노란 화살표, `0x60dc`), B+0x174일 때 B+0x160 깜빡임.
3. 아군 `P+0x98[i]`(+0x54): 같은 방식, 커서 `0x16398`(파란 화살표 = ATB 찬 캐릭터, 노란 화살표 = 아군 대상 선택).
4. 효과/데미지 숫자 `0x19e44`(양 진영) — **메뉴 아님**(데미지 숫자, "miss", "guard" 글, 회복 숫자가 여기).
5. 현재 행동자 화살표 `0x44f20`(vtable+0x40).
6. 화면 흔들기/페이드 `0x2066c`, `0x119e8(game, B+0x1b8)`(밝기, 결과·패배 때 어둡게).
7. 아래 띠:
   - B+0x5c→+0x24==0이면: 현재 ATB 멤버 M에 `M+0x5c bit29 && M+0x1a0==1` → 적 패널 `0x1ee3c`, 아니면 상태 패널 `0x1e0d8(SP, gfx, 1)`; 이어서 `M+0x58&0x900==0`이면 명령 메뉴 `0x1e894`.
   - ATB 찬 멤버가 없으면 상태 패널 `0x1e0d8(SP, gfx, 0)`(이름 열 표시).
8. 적 이름표 `0x1dfec`(B+0x28&0x20).
9. 메시지 상자 MSG vtable+0xc = `0x23120`(→`0x23578`).
10. 상태 0x17이면 결과 화면 `0x1c1ac`.

화면 좌표 공통: 패널 위 y = clipH − 48 = 272. 패널 안 줄 높이 12(큰 배치)·10(작은), 3줄, 첫 줄 y = 272 + (48−36)/2 = 278. **아래 띠는 높이 고정, 폭은 클립 폭 전체, 왼쪽 정렬**(240/512/640에서 글 좌표 같음, 게이지만 늘어남). 캐릭터·적 위치는 폭 비율(주인공 x≈0.78·W, 적은 맵 기준).

## 4. 패널·창

### 4.1 아래 패널 틀 — `0x1df28(obj, gfx)`
- 큰 배치(game+0x160≠0): `0x2ff80(0, H−48, W, 48)`(공용 창 틀). 작은 배치: `0x14184` 세 겹(0x749bb8 / 0xa3d9f0 / 0x40150d) + 안쪽 `0x1415c`(0x5c3030).
- 모든 아래 띠 창(SP, CM 목록, EP)이 먼저 부른다.

### 4.2 상태 패널 SP — `0x1e0d8(SP, gfx, 이름생략)` 【도달】
샷: `command_menu.png`(명령 메뉴와 함께), `panel_name_mode.png`/`target_select.png`(이름 열), `turnmode_command_panel.png`, `w240_command_panel.png`, `defeat_hp0.png`.
- SP: +4 B, +8 스프라이트 시트, +0x10 = 60(내용 시작 x, 명령 메뉴 폭).
- 배치값: 큰 배치 줄높이 12, 단위 6, 글자높이 9, 슬래시 프레임 0x65 / 작은 10,5,7,0x29. **넓음** = 클립 폭 >200(큰)·>190(작은) → 최대값과 '/' 표시.
- 멤버 i(0..P+0xc), y = 278 + 12i:
  1. (세 번째 인자 0일 때) 이름 `0xca2c(game, M, 0, y, x=SP+0x10, 12)` — 화면 x 약 20 "Arc".
  2. HP `0x37b2c(x=60+24, y, 12, S[0], 0x54e0ff00 노랑, 넓음, 1)`; 넓으면 '/' `0x60dc(시트, x, y+(12−9)/2, 0x65)` + 최대 HP S[4].
  3. MP 같은 식, 색 0xfffcab00(옅은 하늘), 최대 M+0xf4.
  4. 게이지(남은 폭 w = W − x − 2(넓으면 −4)):
     - 턴 모드(game+0x14c bit0): MG 막대 하나 `0x37a24(x,y,w,7, 0x40150d00, 0x87707300)` + 채움 `0x3298/0x467c` 폭 (w−2)·MG/MGmax, 색 0x6242ff00(분홍빨강), 가득이면 0x003bff00(주황빨강).
     - 액티브+넓음: 왼쪽 반 ATB(채움 높이 5, 색 0xf5d02f00 하늘, S[0x10]/S[0xc]) + 오른쪽 반 MG(같은 색 규칙).
     - 액티브+좁음: 한 막대에 위 ATB(높이 3) + 아래 MG 선(높이 1).
  - 512 실측: HP "88/104" x≈72, MP "25/25" x≈120, 게이지 y≈281~287, ATB x 157~330, MG x 333~507.
- 숫자 글꼴: `0x37b2c`(→`0x6104` 색 입힌 스프라이트 숫자), 막대 틀 `0x37a24`(=`0x14184`+`0x1415c`).

### 4.3 명령 메뉴 CM — 그리기 `0x1e894(CM, gfx)`, 키 `0x1e594(CM, 키, M)` 【도달】
샷: `command_menu.png`, `command_menu_scroll1.png`, `command_menu_scroll2_flee.png`, `w240_command_panel.png`.
- 항목 5개: 0 Attack, 1 Item, 2 Combi, 3 Guard, 4 Flee. 3줄 보임.
- CM: +4 B, +8 시트, +0xc=3(보이는 줄), +0x10=60(폭), **+0x14 커서**, **+0x1c 스크롤 첫 줄**, +0x20 공격 하위메뉴 열림, +0x24 목록 창 열림, +0x28 공격 하위메뉴 객체, +0x44 bit0 스킬 목록 열림, +0x48 스킬 목록 창, +0x94 아이템/조합 목록 창.
- 틀: 큰 배치면 `0x2fffc({x0=W... }, …)` 좌측 상자(x 0..56, y 275..317), 작은 배치면 `0x1415c` 두 겹.
- 하이라이트: `0x37a24(x=(60−46)/2, y=행y, 46, 11/12, 0xffad9900, 0xe76c5600)`.
- 글: 스프라이트 프레임 `0x5c+i+스크롤`(큰) / `0x12+…`(작은), `0x60cc`로 크기 얻고 `0x60dc` 가운데 정렬. 줄 높이 11(큰)/10. Combi는 B+0x19c==0이면 `0x6104` 회색(0x808080) 틴트.
- 키(내부 코드 = WIPI+0x20): 위/2 이전, 아래/8 다음(스크롤), OK/5 실행, CLR 취소, `*` 아이템 창 바로, `0` Combi, `1` 적 정보 패널 토글, `3/6/9` 단축 스킬(M+0x13d+k → `0x16cd8` 실행), `7` 길게 적 이름표.
- 실행: Attack → 하위메뉴, Item → 목록 창(모드 1), Combi → 목록 창(모드 2, `0x1fa84`; 동료 없으면 무반응), Guard → `M+0x60=0x15`(머리 위 "guard" 효과 글, `guard.png`), Flee → `P+0x7c=1`, 메시지 "도망"(GOT+0x2d4) 후 `0x1a5ec`가 "도망 성공"/"도망 실패".

### 4.4 공격 하위메뉴 — 그리기 `0x1ec54(CM+0x28, gfx)`, 키 `0x1eb40` 【도달】
샷: `attack_submenu.png`, `attack_submenu_hissatsu_disabled.png`, `w240_attack_submenu.png`.
- 항목 2열: 기본(62,293) 스킬(112,293) / 필살(62,306) — DrawString 좌표(`0x3a1c`, 폭과 무관). 사용 불가는 색 0x9d9a(회색). 손가락 커서 스프라이트(`0x60dc`) 항목 오른쪽.
- 상태 패널 영역 대신 그려진다(SP는 틀만).
- 기본 → 대상 선택(4.6), 스킬 → 스킬 목록(4.7), 필살 → 필살 목록(MG 가득+필살기 있을 때만, 없으면 무반응).

## 6. 막힌 점·미확인
- 쓸 수 있는 저장이 초반 1인 파티뿐이라 스킬·필살·조합·레벨업·스킬획득·적 정보 패널을 화면으로 못 봤다. 저장 사본을 고치거나 더 진행된 저장이 필요.
- game+0x160의 정체, 작은 배치 경로 조건, M+0x5c bit29의 출처, 적 `S+0x21` 니블의 뜻은 미확인.
- 메시지 상자와 결과 창의 DrawString 좌표는 그 프레임에 다시 그려지지 않아 calltree로 못 잡았다(스크린샷 실측).
- 액티브 모드에서는 조사 중에도 적이 공격해 두 번 죽었다. 조사는 턴 모드(`gopt.sav` 0x80000221)가 편하다.

## 7. 전투 전에 필드에서 구조를 바꿔 닿은 것(터치 검증)
- 전투 멤버 M은 필드 캐릭터 구조 그 자체다(`M = char`, `char+0x54`가 행동 하위 객체). 전투 중 poke는 되돌려지지만 전투에 들어가기 전 필드에서 `char`를 바꾸면 그대로 들어온다. 파티 `[game+0x1c0]`, 캐릭터 8명이 `0x42c24c + 0x1a4*id`에 이미 있다(b512 저장, 첫 필드 기준).
- 동료 넣기: ctrl `gcall 1a0b0 <파티> <캐릭터>`(필드 `전투동료설정`이 쓰는 파티 객체 추가). 그 뒤 슬롯 `party+0x84+4*k`와 전투 순서 `party+0x98+4*k`에 모두 들어간다.
- 스킬: `char+0x160`(id 바이트, 0xff 끝), `+0x174` 수, 필살 `+0x178/+0x17c`, 단축 `+0x13d..`, 능력 `+0x5c |= 0x20000000`(적 정보), MG `+0xf8`=최대, 조합 습득 비트 `party+0xb8+(id>>3)`. 조합 후보는 스킬 플래그 `0x400000`이고 하위 바이트에 행동자와 동료의 캐릭터 번호 비트가 모두 있어야 한다(아크+제레이 70, 아크+라즈파샤 75·76).
- 결과: `char+0x104`(현재 EXP)를 `+0x108`(다음 레벨) 직전으로 두고 이기면 쪽 1(LV UP)과 쪽 2(스킬 획득)가 둘 다 선다(`M+0x154`, `+0x158`).
- 키 방향 확인(실제로 눌러 봄): 스킬 목록은 ↑ = 앞으로, ↓ = 뒤로, 끝에서 순환. 조합 목록은 고르기 전(`B+0x198` != 2)에는 ↑↓가 듣지 않고 OK가 고르기 상태(2)로 넘기며, 그 뒤 ↑↓는 순환하지 않는다.
