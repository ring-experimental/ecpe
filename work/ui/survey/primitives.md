# UI 그리기 프리미티브 (Part 1)

주소는 `client.bin` 파일 오프셋(게스트 = +0x100000). 인자는 r0~r3, 이어서 `[sp]`, `[sp+4]` … (호출 시점 기준). 모두 역어셈블(`tdis.py`)로 읽고, 필드 메뉴·아이템 화면에서 `calltree`와 `memdump`(실행 폴더 `work/ui/run/prim/g`, 512 폭)로 확인했다. 확인 방식이 다른 항목은 따로 적었다.

도구와 산출물은 `work/ui/run/prim/`에 있다. `sa.py`는 함수별 정적 분석(직접 호출, API 호출, GOT/문자열 참조, vtable 저장)을 해서 `sa.json`을 만든다. `mem.py`는 memdump를 읽는 도우미다. `g/*.bin`, `g/ct_*.txt`는 메모리 덤프와 호출 나무다.

## 0. 공통 규칙

- PIC 코드라 `sl` = GOT 시작(`0x4e624`)이다. 데이터 포인터는 `GOT[off]` 값 + `0x1254`이 파일 오프셋이다(게스트 = `0x101254 + 값`). 코드 포인터도 같다(+0x1254, thumb 비트).
- WIPI API는 `GOT[0x44]` → 전역 `0x4dce0`(그래픽 표)이고, 번호 = 오프셋/4다. 쓰는 것: 6 SetContext, 7 GetContext, 8 PutPixel, 17 DrawString, 21 FlushLcd, 22 GetPixelFromRGB, 24 GetDisplayInfo, 30 GetStringWidth. **FillRect, DrawRect, DrawLine, CopyArea API는 전혀 쓰지 않는다.** 사각형, 선, 블릿은 모두 게임이 프레임버퍼 메모리에 직접 쓴다. 그래서 calltree의 API 잎에는 글자만 보이고, 창과 스프라이트는 guest 함수 이름(`6b4c`, `6e60` …)으로만 보인다.
- **색 값**: 32비트 `0xBBGGRRxx`(최하위 바이트는 쓰지 않음). 예: `0x5c303000` = RGB(0x30,0x30,0x5c) 남색 창 바탕, `0xffffff00` = 흰색. RGB565로 바꾸는 것은 API 22다.
- 직사각형 구조 `rect` = `{s32 x, y, w, h}` 16바이트. 만드는 함수: `0x3298(rect*, x, y, w, [sp]=h)`.

## 1. 객체 모델

### 앱 객체(Clet) — 전역 `GOT[0x294]` → `0x14ee34`, 값 `0x400020`
`0x144b0()`이 이 포인터를 돌려준다. 거의 모든 프리미티브가 gfx 인자가 0이면 이것의 `+0x34`를 쓴다.

| 필드 | 뜻 |
|---|---|
| +0 | vtable/콜백 (`0x6604` = 틱) |
| +0x34 | **gfx 객체**(아래) |
| +0x38 | **입력 객체** |
| +0x3c | 사운드 관리자 |
| +0x48 | **월드 객체 W**(RPG 상태 전체) |
| +0x58 | 프레임 카운터 |

틱 흐름: `0x6604 → 0x6720`. `0x6720`은 `bba0(W, input)`(장면 실행), `40c4(gfx)`(FlushLcd), `613c(input)`(키 상태 정리), 사운드를 차례로 부른다.

### 장면 전환 — `0xbba0(W, input)`
- `W+0xc` = 현재 장면 번호, `W+0x10` = 장면 안 하위 단계(장면 함수가 직접 `str`로 바꾼다. 예: `0x10674`는 W+0x30의 이벤트 번호가 1000 미만이면 9, 아니면 10으로 보내고 끝나면 11).
- `W+0x2b0 + 4*번호` = 장면 틱 함수표(`0xe390`이 채운다). 함수 서명은 `f(W, input)`.
- 덤프에서 읽은 표:

| 0 | e588 | 오류 화면 「프로그램오류!!!」 |
| 1 | e5e4 | 로고/인트로(효과 애니) |
| 2 | e85c | 타이틀 배경 |

### 월드 객체 W(앱+0x48) 주요 필드
`+8` gfx, `+0xc/+0x10` 장면, `+0x14` 플래그, `+0x30` 이벤트 번호, `+0x174` 스크립트 실행기, `+0x194..` 파티원 8명, `+0x1c0` 파티/인벤토리, **`+0x1cc` 아이템 DB, `+0x1d0` 스킬 DB, `+0x1d4` 필드 메뉴 객체**, `+0x318` 아이템 설명 문자열 풀, `+0x31c` map.pmd, **`+0x324` dataset.dat 객체(스프라이트·아이템·스킬 표)**, `+0x32c` script.bin.

### 키 입력
`handleInput 0x1447c(type, p1, p2)` → `0x6284 → 0x62a8(app, type, p1, p2)`.
- type 2(누름)는 `6584`, type 3(뗌)은 `65c4`, 0x5001/0x5002는 resume(`6554`)/pause(`64f8`)로 간다.
- 키 코드는 `code+0x20`으로 저장한다. 예외: RSK(-7)와 0x10004는 OK(-5)로, 0x10005는 CLEAR(-16)로 바꾼다. 저장은 `61a0`이 입력 객체에 한다. **입력은 전달되지 않고 장면이 매 프레임 읽어 간다.**
- 입력 객체: `+0` u16 이번 프레임 누른 키, `+2` u16 상태(1=눌림), `+4` 뗀 키, `+0xc` 사용 가능, `+0x14` 누르고 있는 프레임 수.
- `61d4(input)` → 막 누른 키(+0x20 코드, 41곳에서 부름). `6204(input)` → 누르고 있는 키 | (프레임수<<20). `61b8(input)` → 키 이벤트가 있는지.
- 코드값: UP 0x1f, DOWN 0x1e, LEFT 0x1d, RIGHT 0x1c, OK 0x1b, LSK 0x1a, CLEAR 0x10, '*' 0x4a, '#' 0x43, '0'~'9' 0x50~0x59.
- 필드 메뉴: 장면 14 `109b8` → `2fa60(menu, input)` 갱신 → `2faa4(menu)` 그리기(화면 객체 vtable[1]) → `2fb1c`. 화면 객체 vtable 슬롯은 `[0]` 소멸자, `[1]` 그리기 `(this, gfx)`, `[2]` 갱신/키 처리.

## 2. gfx 객체(앱+0x34, 덤프에서 `0x42b94c`)

| 필드 | 뜻 |
|---|---|
| +0 | 앱 포인터 |
| +8/+0xc | 화면 w, h(512, 320) |
| +0x20 | 글꼴 |
| +0x24 | 글줄 높이(12) |
| +0x30 | **글자 색**(`3f14(gfx,col)`이 바꾸고 옛 값을 돌려준다) |
| +0x34 | 보조 값(`3f0c`, 용도 미확인) |
| +0x38/+0x3c | 흐르는 글 오프셋/틱(`3b40` 리셋) |
| +0x40 | **그리기 표면**: +0 화소 포인터(RGB565), +4 w, +8 h, +0xc 한 줄 바이트, +0x10/+0x14 원점 이동(= gfx+0x50/+0x54, `37e0`이 더한다), +0x18 투명색 0xf81f |
| +0x64 | 프레임버퍼 핸들(DrawString용) |
| +0x8c | WIPI GC(SetContext 0=클립, 1=전경색) |
| +0xcc | **글자 클립**(`39ac(gfx,rect)` 설정, `39c8(gfx)`는 +0xdc로 되돌림) |
| +0xdc | **그리기 클립 = 화면 사각형**(0,0,w,h). 블릿과 채우기가 이것으로 자른다. `3848(gfx,x,y,w,[sp]h)` 설정, `3900` 넣기(옛 값은 +0xec), `3994` 빼기, `37f4(gfx,&w,&h)` 읽기, `39fc(gfx,&pt,dx,dy)` 화면 가운데+오프셋 |
| +0xfc | 프레임 머리 임시 |
| +0x108 | 블릿 기술자 임시 |
| +0x118.. | 색 효과 표 |

메서드 표 `+0x13c..+0x184`는 `0x3454`(gfx 초기화)가 RGB565용 표를 채운다. 첫 인자는 항상 `gfx+0x40`(표면)이다.

| 슬롯 | 함수 | 감싸는 함수 | 뜻 |
|---|---|---|---|
| 0x13c | 6ac4 | | 화소 주소 |
| 0x140 | 6adc | | 점 찍기(x,y,col) |
| 0x148 | 6b4c | `467c(gfx,rect,col)` | **사각형 채우기** |
| 0x14c | 6bd8 | `4714(gfx,rect,col)` | **사각형 테두리** |
| 0x150 | 6cbc | `4760(gfx,pt1*,pt2*,col)` | **선**(pt = {x,y}) |
| 0x154/158/15c/160 | 6e60/6f6c/707c/7190 | `4798/4838/47e8/4888` | 블릿(보통/좌우 뒤집기/상하/둘 다) |
| 0x164 | 7430 | `49a8` | 효과 블릿 |
| 0x170 | a190 | `46c8(gfx,rect,col)` | **50% 반투명 채우기**(팝업 뒤 어둡게, 234c4는 검정 0x40000000) |
| 0x174 | a2d4 | `4c74` | 팔레트/색 변환 복사 |
| 0x17c | a928 | `4934(gfx,rect,col)` | 영역 색 효과(스크립트 bfe8) |
| 0x180 | a44c | `48fc` / 49a8 | 색조 바꾸기 |
| 0x184 | abd0 | `4c9c(x,y,size,col)` | 작은 점/원(스크립트 147e0) |

`0x40c4(gfx)`가 FlushLcd로 화면에 낸다. 진단용 PutPixel(0,0)과 (w-1,h-1)이 calltree에 보인다.

## 3. 글자

글꼴은 플랫폼 글꼴 하나(줄 높이 12, 기준선 = y + 12 - 3)다. 그리기는 모두 WIPI `DrawString`이고 비트맵 글꼴은 없다(숫자는 아래 비트맵 숫자 참고).

- **`0x3a1c(gfx, x, y, const char*)`**: 한 줄을 (x,y) 왼쪽 위에 그린다. 색은 gfx+0x30, 클립은 gfx+0xcc, 원점 이동을 적용한다. 정렬이나 줄바꿈은 하지 않는다. 30곳에서 부른다.
- **`0x3ecc(gfx, const char*)` → 폭(px)**: GetStringWidth.
- **`0x3c0c(gfx, rect*, String*, flags)`**: 글 상자. rect가 0이면 gfx+0xdc를 쓴다. 단어 단위로 줄을 감싸고(`2484(String*, w)`가 다음 줄을 새 String으로 돌려준다), 줄 간격은 12+2다.
  - flags `0x2` 가로 가운데, `0x10` 오른쪽 정렬(`3d68`이 처리), `0x100` 세로 가운데(줄 수는 `2314`로 셈), `0x20` 한 줄만.
  - 예: 필드 메뉴 지역 이름 `31508`은 `0x122`(가운데 + 세로 가운데 + 한 줄).
- **`0x3d68(gfx, x, y, clip16*, [sp]=String* 줄, [sp+4]=flags)`**: 한 줄을 정렬해 그린다. 안에서 GC 클립(SetContext 0)과 색을 바꾸고 DrawString을 부른다. clip16은 `{s16 x,y,w,h}`다.
- **`0x3bb0(gfx, rect*, const char*, flags)`**: char*를 임시 String으로 감싸 `3c0c`를 부른다.
  `0x3bf0(gfx, x, y, w, [sp]=h, [sp+4]=char*, [sp+8]=flags)`는 rect를 만들어 `3bb0`을 부른다.
  **`0x14240(x, y, w, h, [sp]=char*, [sp+4]=flags)`**는 기본 gfx로 `3bf0`을 부른다(메뉴가 가장 많이 쓰는 형태).
- **`0x3b48(gfx, rect*, char*)`**: 폭이 넘치면 흐르는 글(10프레임 멈췄다가 4px/프레임). 아이템 설명 `32338`에서 쓴다.
- **String 객체**(8~16바이트): `+0` 버퍼, `+4` char*, `+8` 할당기, `+0xc` 커서. `28b8(s,0)` 생성, `29b8(s,char*)` 대입, `2958(s)` 해제, `2144/215c`는 스택 String 생성/해제.
- **글 형식**: CP949. `21cc`(줄 자르기)는 최상위 비트가 켜진 바이트를 2바이트 글자로 보고, `\n`, `\r\n`에서 줄을 바꾼다. 줄 첫 바이트가 `0x08`이면 폭 계산에서 뺀다(제어 문자로 보이나 그리기 쪽에는 처리가 없다). **메뉴 글 경로에는 색 코드나 아이콘 삽입이 없다.** 색은 부르기 전에 `3f14`로 바꾸고 다시 되돌린다(아이템 탭: 선택 0xffffff00, 나머지 0xf0aea100).
- 이벤트 스크립트 글(`13c58`, `13e48`)은 따로 해석한다.
  - `,` … `\`: 앞부분을 따로 떼는 이름/머리표.
  - `\x`, `\y`, `\w`: 종류 0/1/2. `\z`: 끝.
  - `,`로 나뉜 두 칸 배치.
  - 금색(0x76b4d600) 8방향 + 검정 가운데로 그리는 **외곽선 글자**.
  - 대사창 자체는 대사창 담당 조사에서 확인할 것.
- **비트맵 숫자 `0x37a78(x, y, value, color, [sp]=right?, [sp+4]=간격)`**: UI 스프라이트(필드 메뉴 객체+4 슬롯 = dataset 스프라이트 5) 프레임 0x27의 5×7 숫자 띠에서 `subrect(x=digit*5)`로 한 자리씩 오른쪽부터 그린다. 색 효과 플래그 0x08000000으로 색을 바꾼다. 기본 간격은 4px. 감싸는 함수는 `118cc`. 아이템 개수, 가격, 능력치 숫자 대부분이 이것이다. 「x9」 같은 작은 숫자.

## 4. 창 장식(모두 프로그램으로 그린다. 9-slice 이미지가 아니다)

- **`0x2ff80(x, y, w, h)`: 메뉴 창**. 바깥부터 1px 테두리 4겹(`14184`)이고 색은 GOT[0x434] → `0x4aa20` 표(RGB): (0x22,0x25,0x40) 짙은 남색, (0xf0,0xd9,0xa3) 금색, (0x94,0x8a,0x9c) 회보라, (0x0d,0x15,0x40). 안쪽(x+4,y+4,w-8,h-8)은 (0x30,0x30,0x5c)로 채운다. 36곳에서 부른다.
- **`0x1415c(x, y, w, h, [sp]=col)`** 채우기, **`0x14184(x, y, w, h, [sp]=col)`** 테두리(기본 gfx). 그 아래는 `467c/4714`.
- **`0x37a24(x, y, w, h, [sp]=테두리색, [sp+4]=채움색)`**: 테두리 1px + 안 채움. 두 색이 같으면 기본값 테두리 (0x99,0xad,0xff) 하늘색, 채움 (0x56,0x6c,0xe7) 파랑을 쓴다. **선택 막대/커서 하이라이트**다(아이템 목록 `31cec`가 선택 줄에 (x+4,y+16*i+4,0x70,0x10)로 그림). 게이지 바탕에도 쓴다.
- **`0x2fffc(pt1*, pt2*, 두께?)`**: 3색 구분선(금, 회보라, 남색 선 `4760`).
- **`0x46c8(gfx, rect, col)`**: 반투명 어둡게(팝업 뒤 `234c4`, 필드 장면 `12b18`).
- **키 도움말 바 `0x302b4(P_ui, x, y, mode 0..9, [sp]=h)`**: `2ff80` 창(폭 120)을 그리고, 모드별로 UI 스프라이트 합성 프레임을 놓는다(0x46 OK 아이콘, 0x52, 0x5b … 「OK:사용」 「*:핫슬롯」 「Help/Exit/저장/이전」 같은 **글자도 그림 프레임**이다). 필드 메뉴는 `30884(screen, ?, mode)`로 메뉴 원점+(0,0x7d), 높이 0x15에 그린다. 「CLR : 나가기」 「CLR : 취소」 「OK : 계속」 문자열은 랭킹(`134cc`)과 첫 실행(`10ef0`)에서만 글자로 그린다.
- 탭 화살표, 메뉴 아이콘, 탭 머리 그림은 모두 UI 스프라이트 프레임이다(`31238`: 프레임 0x1e/0x1c/0x1b와 flip 1로 좌우 화살표, 0x45 합성).

## 5. 스프라이트/이미지

### 자료 구조(덤프로 확인)
- **슬롯 X**(애니 상태): `+0` 애니 id, `+4` 애니 인덱스(-1=없음), `+8/+0xc` 프레임 카운터, **`+0x10` 스프라이트 P**. `5f80(X,P)` P 지정, `5f48(X,animId)` 애니 지정, `5f10` 초기화.
- **스프라이트 P**(0x18바이트, dataset 객체 +0x54[id]):
  - `+0` 머리. byte0 id, byte2 프레임 수, byte3 애니 수.
  - `+4` 프레임 포인터 배열.
  - `+8` 애니 표.
  - `+0x10` **이미지 머리 배열**(12바이트씩).
  - `+0x14` **팔레트 표**(32바이트 = RGB565 16색씩, 전역 공유).
- **프레임**: `u32 n` + n×`{u8 flip(bit0 좌우, bit1 상하), u8 이미지번호, s8 dx, s8 dy}`.
- **이미지 머리**: `u8 w, u8 h, u16 팔레트번호, u32 화소 포인터, u32 flags`.
  - flags bit0 = 16bpp 직접 색. 0이면 **4bpp**로, 한 줄 = (w+1)/2바이트, 짝수 화소 = 아래 니블, 홀수 = 위 니블(`72a8/72e8`).
  - bit1 = 0번 색 투명.
- **블릿 기술자 desc**(16바이트): `{hdr*, s16 sx, s16 sy, …, +0xc 팔레트 포인터}`.

### 그리기 함수
- **`0x48d8(gfx|0, x, y, desc*)`**: desc를 (x,y)에 그린다(w,h는 hdr에서). 가장 낮은 단위다.
- `0x4798/4838/47e8/4888(gfx|0, dstRect*|0, desc*)`: 보통/좌우/상하/둘 다 뒤집기. 클립은 gfx+0xdc. 안쪽 흐름은 `45f4`(클립 계산) → `39e4` → 표면 슬롯 0x154~0x160.
- `0x49a8(gfx|0, dstRect*, desc*, fx*)`: 효과 블릿. fx+0 플래그: 1 = 배율(+0x10 %), 4/8 = 뒤집기, 0xfc000020 = 색 효과(슬롯 0x180), 0x2fff200 = 기타(슬롯 0x17c).
- **`0x5810(P, x, y, frame, [sp]=flip, [sp+4]=subRect*|0)`**: 단일 이미지 프레임(첫 부분만). **`0x60dc(X, …)`**는 같은 일을 X+0x10으로 한다(45곳).
- **`0x56ec(P, frame, x, y, [sp]=dx, [sp+4]=dy, [sp+8]=flip)`**: 합성 프레임(부분 오프셋 적용, 33곳). 창 장식, 키 도움말, 타이틀이 쓴다.
- `0x58dc/0x6104(X)`: 효과판(fx*는 `[sp+8]`), 숫자 그리기가 쓴다. `0x5f84/5ae8/5ffc`: 애니 재생.
- `0x2df44(?, flags, rect, desc, [sp]=fx)`: 타일 블릿(flags 0x800 좌우, 0x1000 상하).

### 리소스 → 핸들
- **dataset 객체**(W+0x324, 클래스 `21c98` 「dataset.dat」, vtable 4d8d4):
  - `+0x24` 스프라이트 수(104), `+0x54` P 배열, `+0x58` id → 묶음 번호, `+0x3c+4g` 묶음을 읽었는지.
  - **`0x221dc(ds, id)` → P**: 필요하면 `22104 → 22050`이 묶음을 풀어 `5438`로 P를 만든다.
- **UI 그림 = 스프라이트 5번**(덤프 0x437380): 프레임 102개, 이미지 159개. 머리 글자, 화살표, 아이콘, 키 도움말, 숫자 띠(프레임 0x27)가 들어 있다.
- 메뉴 객체(W+0x1d4)+4가 이 스프라이트의 슬롯 X이고, 화면 객체 +8이 같은 X를 가리킨다.
- 덤프 당시 읽혀 있던 스프라이트: 0, 1, 2, 4, 5, 7, 8, 10, 39, 81, 82, 84. 큰 것은 0(108×219), 4(152×105), 81(144×103), 7(88×110). 초상화나 몬스터로 보이며, 무엇인지는 화면별 조사에서 확인할 것.
- 파일:
  - dataset.dat: "1001" 묶음. 앞 0x490은 지역 이름 표(평문 CP949, 28바이트), 그 뒤는 압축 블록(스프라이트 묶음, 아이템/스킬 표).
  - res.gmf: 소리(README).
  - script.bin: 대사/스크립트.
  - tileset.pts, map.pmd: 맵.
  - 블록 읽기는 `22c4c`(공통), 파일 열기는 vtable[1] `20aa4`.

### 그림 하나만 떼어 그리는 최소 호출(host 래퍼 제안, 아직 실행해 보지 않음)
1. `P = f_221dc(ds = R32(W+0x324), spriteId)`(이미 읽혀 있으면 `R32(R32(ds+0x54)+4*id)`). W는 `R32(R32(0x14ee34)+0x48)`.
2. gfx = `R32(app+0x34)`. 클립 +0xdc를 원하는 영역으로 둔다(`f_3900` 넣기 / `f_3994` 빼기). 영역을 `f_467c(gfx, rect, 색)`이나 표면 memset으로 지운다.
3. 단일 프레임은 `f_5810(P, x, y, frame, [sp]=0, [sp+4]=0)`, 합성 프레임은 `f_56ec(P, frame, x, y, 0, 0, 0)`이다. 프레임 대신 이미지 번호 하나만 그리려면 desc = `{P+0x10 + 12*img, 0, 0, 0, P+0x14 + 32*u16(hdr+2)}`를 게스트 메모리에 만들고 `f_48d8(0, x, y, desc)`를 부른다.
4. 화소는 `gfx+0x40` 표면(+0 포인터, +0xc 줄 바이트, RGB565)에서 읽는다. 4bpp 0번 색 투명 이미지는 지운 색이 그대로 남으므로 바탕을 0xf81f(자홍)로 지우면 알파를 구할 수 있다.
