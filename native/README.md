# 에픽크로니클PE 네이티브 빌드

WIE와 ARM 에뮬레이터 없이 도는 SDL3 빌드다. 구조는 크로노스 윙 네이티브 빌드([ring-experimental/chronos-wing](https://github.com/ring-experimental/chronos-wing)의 `native/`)와 같다. 게임 코드는 `client.bin1236`을 기계 번역한 C(`build/tr.c`)이고, WIPI API는 `host/`에서 직접 구현한다.

```bash
make -j8 JAR=<010100D5.jar>    # 원본 jar(기본값: 저장소 루트의 origin/010100D5.jar, .gitignore)
build/ecpe                     # 전체화면(높이 320, 폭은 모니터 비율, 늘 가로가 길다). --windowed(같은 폭의 창), --touch(화면 패드), --width <폭>(240·320은 원작 대조 시험용), --save <폴더>, F11 전환
```

키: 방향키, Space/Enter=OK, Shift 좌/우=소프트키, Backspace/Esc=CLEAR, 123/QWE/ASD/ZXC=숫자 키패드, F1=조작 설정, F3=기타 설정(전투 보상 배율), F5=퀵세이브(필드), R=자동 전투, F=전투 2배속, Tab=대사 AUTO, Ctrl=대사 SKIP. 마우스로 메뉴 항목을 누를 수 있다(아래 '터치와 게임패드').

## 가로 전체화면

게임이 `GetDisplayInfo`로 화면 폭을 읽어 메뉴, 대사창, 필드, 전투 배치를 스스로 넓게 그린다. 필드는 맵이 화면보다 좁으면 양옆이 검게 남는다(원본 그대로). 원작 그리기에서는 메뉴와 창이 240 폭 그대로 가운데 놓인다(아래 '메뉴 현대화' 참고).

먼저 전투를 고쳤다(`restored/battle.c`). 전투 무대는 14px 타일 23칸(322px) 맵이고, 전투는 갱신 격자에 표시된 타일(스프라이트가 지나간 자리)만 다시 그린다. 캐릭터, 데미지 숫자, 효과는 화면 폭 비율로 놓이므로 폭이 322를 넘으면 맵 밖 빈 곳에 그려지고, 그곳은 격자 밖이라 지워지지 않아 잔상이 남았다. 전투 맵을 읽을 때 격자를 양옆으로 넓히고(`0x205c4` 감쌈), 맵 그리기(`0x3892c`)는 넓힌 칸에 맵 끝을 거울처럼 접은 타일을 그린다. 원본은 맵 카메라가 음수일 때 표시(카메라 기준)와 그리기(가운데 기준)가 어긋나므로, 넓힌 경우에는 그리기도 카메라 기준으로 맞춘다. 폭 322 이하에서는 원본과 같다.

필드 뒷배경도 고쳤다(`restored/fieldbg.c`). 필드 맵은 투명 타일 자리에 뒷배경 레이어(하늘, 먼 산)를 비춰 그리고(`0x381a0`) 화면을 매 프레임 지우지 않는다. 뒷배경은 x=0부터 그 레이어 폭(첫 필드는 25칸, 350px)만큼만 그려져서 넓은 화면에서는 오른쪽 투명 자리가 지난 프레임 그대로 남아, 스크롤하면 절벽 타일이 끌린 잔상이 생겼다. 레이어 밖 칸은 레이어를 되풀이해 채운다(거울로 접으면 타일이 뒤집히지 않아 구름이 끊긴다).

연출용 뒷배경도 같은 식으로 채운다(`restored/backdrop.c`). 필드 장면 상태(장면 `+0x18`)가 5이면(이벤트 스크립트 명령 `0xcc94`) 뒷배경 레이어를 먼저 통째로 깔고(`0xcdf0` → `0x38418`) 맵은 투명 타일을 건너뛰며 그린다. `0x38418`은 레이어를 보기 가운데에 레이어 폭만 그려서 넓은 화면에서는 양옆 투명 자리에 지난 프레임이 남는다. 원본을 부르기 전에 양옆을 레이어를 되풀이해 채운다. 가진 저장으로는 이 상태에 닿지 못해, 첫 필드에서 상태를 강제로 5로 바꿔 확인했다.

이벤트 장면의 좁은 맵도 고쳤다(`restored/widemap.c`, `0x2ee2c`·`0x2f7c4`·`0xcc94` 감쌈). 240 폭에 맞춘 22~23칸(308~322px) 맵은 넓은 화면에서 가운데 놓이고 양옆은 `0x2f7c4`가 검게 칠한다.
- 불꽃놀이(맵 88, 스크립트 5의 명령 `0xb4`~`0xb7`): 불꽃은 보기 사각형 전체를 클립으로 그리고, 꺼질 때는 화면을 지우지 않고 점을 밤하늘 색까지 어둡게 덧칠해 없앤다(`0x14a30`/`0x14a68`, 맵은 `G+0x1c` 비트 0이 켜진 틱에만 다시 그린다). 맵 밖 검은 여백에 떨어진 점이 하늘색 잔상으로 남았다. 이 맵은 가로로 되풀이되는 그림이라 카메라를 맵 폭만큼 옮겨 원본 그리기를 더 불러 좌우를 맵으로 채운다.
- 연출 뒷배경(장면 상태 5, 노을 장면 맵 72): `backdrop.c`가 양옆을 채워도 뒷배경 그리기(`0x38418` → `0x2ec68`)와 맵 그리기가 좌우 여백을 검게 덮고 그 위에 노을 그라데이션만 섞여 가운데와 어긋났다. 이 상태에서는 좌우 여백을 칠하지 않는다(위아래는 원본대로).
- 연출 뒷배경은 그리기 틀을 가운데 146줄 띠로 줄인다(`0xcc94` → `0x389c`: 원점 gfx `+0x50/+0x54`, 크기 `+0x44/+0x48`). 띠 밖에 앞 화면이 남지 않게 줄이기 전에 화면을 지운다. 대사창 래퍼는 이 틀 때문에 초상이 띠 안쪽만 리마스터 그림으로 바뀌고(클립 좌표가 화면 좌표와 어긋남) 이름이 본문 첫 줄로 들어갔다. 초상을 떼는 동안 틀을 화면 전체로 돌려놓고, 이름표를 가르는 y에 틀 원점을 더한다(`restored/ui_dialog.c`).
- 이벤트 장면 바로 보기: `work/tools/toscript.sh <폴더> <스크립트 번호> <파일 오프셋>`(저장 사본에서 script.bin 항목을 게스트 메모리에 올려 그 자리부터 실행, ctrl 명령 `loadbin`). 불꽃놀이 `5 228`, 노을 `6 d78`·`14 1694`. 스크립트 명령 번호 → 처리기는 `0x3a4a4`의 분기표(GOT-0x25e0, 명령-0x3e).

맵에 들어설 때의 카메라도 고쳤다(`restored/camera.c`). `0x2f3e4`는 카메라를 주인공 가운데에 놓고, 게임 플래그(`+0x20`의 0x10)가 켜져 있을 때만 맵 안으로 가둔다(`0x2ea20`). 맵에 막 들어섰을 때는 꺼져 있어서, 넓은 화면에서는 보기의 절반이 맵 끝을 넘어 한쪽이 검게 비었다가 첫 걸음에 화면이 튄다(수도 아멜고에서 집을 나올 때 오른쪽 60px). 원본 폭(240)이었다면 맵 밖이 보이지 않았을 카메라만 가로로 가둔다. 세로는 원본과 같다(원본도 들어설 때 세로는 가두지 않는다).

코드에는 240이나 320 같은 화면 크기 상수가 없다(상수 검색에 걸리는 것은 모두 구조체 오프셋이다). 넓은 화면에서 어긋나는 곳은 240 폭에 맞춘 데이터(맵, 레이어)와 매 프레임 다 그리지 않는 영역이 겹치는 곳뿐이었다. 필드 맵 그리기(`0x2ee2c`)는 카메라가 음수이면 맵을 화면 -카메라 자리에 놓으므로 스프라이트와 어긋나지 않고, 맵 밖 여백은 매 프레임 칠한다(`0x2ec68` → `0x2f7c4`).

`restored/`는 크로노스 윙과 같은 방식이다. `list.txt`의 함수는 번역에서 빠지고(`wrap`이면 `orig_f_<오프셋>`으로 남고) 읽는 C로 대신한다.

## 메뉴 현대화(RmlUi)

타이틀, 필드 메뉴(아이템·스킬·장비·스테이터스·퀘스트·전투파티·옵션), 상점, 대화·선택지·알림, 전투 창은 RmlUi 문서로 다시 그린다. 입력과 상태는 원본 코드가 그대로 처리하고 그리기 함수만 감싼다(`restored/ui_<영역>.c`, `restored/list.d/<영역>.txt`, 문서는 `ui/`). 규칙과 작업 방법은 `ui/README.md`, 원본 화면 조사는 `work/ui/survey/`에 있다.

- 영역: system(옵션·저장·예/아니오), fmcore(메뉴 분배·메인·아이템·장비), fmchar(스킬·스테이터스·퀘스트·전투파티), shop, title, dialog(대화·선택지·알림·미니맵·필드 표시), battle.
- F2, `--classic`, ctrl 명령 `ui classic|modern`으로 원작 그리기와 오간다.
- **필드 메뉴 틀**(사용자 결정 2026-11-11, `restored/fm_shell.c`, `ui/fm_shell.rml`, `ui/fmshell.rcss`, 자세히는 `ui/README.md` '필드 메뉴 틀'): 모드 1의 화면 0~7에 왼쪽 레일(메뉴 7개 + 소지금·시간·장소), 캐릭터 화면 위의 캐릭터 띠, 아래 고정 버튼 띠(오른쪽 끝 「이전」, 그 왼쪽 「결정」이 늘 같은 자리)를 둔다. 원본 상태 기계는 그대로 두고 래퍼가 필드 메뉴 키 분배 `0x2fa60`을 같은 틱 안에서 동기로 불러(`fm_key_raw`) 메인의 대상 선택, 스킬의 분류·동작 고르기, 아이템의 설명 단계를 화면에서 없앴다. 레일·칩은 어느 상태에서든 바로 그 화면·캐릭터로 간다. 장비 강화·귀환 주문서·망각의 물약·프리미엄 상점도 틀 안(내용 자리 + 고정 버튼 띠)에 뜨고, 떠 있어도 레일을 누르면 창을 닫고 바로 그 화면으로 간다(레일 잠금 없음). 「이전」은 보이는 구조에서 한 단계 위(팝업 등이 없으면 홈). 마우스 오른쪽 = 이전, 패드 LB/RB 레일·LT/RT 캐릭터(틀이 떠 있으면 틀이 이긴다), 키보드 Tab/Shift+Tab 레일·`[ ]` 캐릭터.
- 새 배치의 방향이 원본 키와 다른 화면은 키 별칭(`ui_key_alias*`, `host/ui.h`)으로 맞춘다. 그 문서가 보이는 동안 호스트(`main.c` `send_key`)가 키를 바꿔 넘기고 원래 키도 그대로 둔다. 필드 메인 메뉴(세로 메뉴·파티, 원본은 좌우)는 ↑↓/2·8을 ←→/4·6으로, 저장/불러오기 고르기와 슬롯(가로, 원본은 상하)은 ←→/4·6을 ↑↓/2·8로 받는다(예/아니오 대화 중에는 바꾸지 않는다).
- 렌더러(`host/ui_render.cpp`)는 transform을 정점에 직접 적용하고, transform이 걸린 요소 안의 자르기(RmlUi 클립 마스크)는 마스크 도형의 외곽 사각형으로 한다(SDL_Renderer에 스텐실이 없다). 전에는 둘 다 빠져 있어 등장 효과(`.pop`) 동안 초상화 같은 overflow 자르기가 풀렸다.
- 환경설정의 퀵모드는 새 UI에서 뺐다(항목 없음, 저장 값은 건드리지 않음).
- 옵션의 「저장/불러오기」 한 칸을 「저장」「불러오기」 두 줄로 나눴고, 고르면 바로 슬롯 화면, 슬롯을 고르면 묻지 않고 저장·불러오기를 한다(사용자 결정). 원본 상태는 그대로 두고 키 처리기(`0x34f48`)를 감싸 고르기 단계의 OK와 예/아니오의 예를 덧보낸다(`restored/ui_system.c`).
- 옵션 하위 화면의 깊이를 줄였다(사용자 결정): 왼쪽 목록은 어느 하위 화면에서든 바로 누를 수 있고(`pick="opt"`, 래퍼가 CLR로 나와 그 줄로 들어간다), 환경설정 값은 바꾸는 즉시 적용·저장한다(원본 OK로 적용하고 다시 들어가 같은 줄로). 터치에서는 확인·이전 버튼 없이 "나가기" 하나다.
- 타이틀 메인 메뉴는 틀이 고정이다(2026-11-10 사용자 요청, 다른 게임 메뉴 참고: Octopath·Xenoblade 설정의 왼쪽 분류 + 오른쪽 내용, FF 픽셀 리마스터의 항목 설명과 뮤직 플레이어, 콘솔 공통의 오른쪽 아래 고정 버튼 안내). 왼쪽 레일(메인 5항목)과 오른쪽 패널(머리 띠 위치 + 하위 목록 + 내용 칸)은 단계와 상관없이 같은 자리·크기이고, 메인에서 커서를 옮기면 패널에 하위 목록·설명·저장된 설정을 흐리게 미리 보인다. 하위 항목에는 새 UI가 붙인 한 줄 설명이 있다(`restored/ui_title.c` `DESC_*`). 키 안내는 「결정」「이전」 두 칸 고정(쓸 수 없으면 흐림, 터치는 「이전」만), 쪽 안 조작(◀▶, ▲▼, 1/2)은 쪽 안에 둔다. 에픽 OST는 곡 목록 + 곡 정보(듣는 곡 ♪)를 한 칸에 둔다(L8과 L12가 같은 모양). 원작과 다른 동작: 게임종료는 패널에서 한 번 확인한다(첫 OK를 막음), 환경설정은 CLR로 나가도 저장한다(CLR을 OK로 바꿈). 보이는 칸은 모두 바로 누른다(사용자 결정): 고르는 중이 아닌 칸·위치 띠는 `pick="tmenu"`(idx = 레벨×16 + 칸)로, `f_ebc4`가 목표가 지금 단계의 아래면 사슬의 칸에 커서를 두고 OK로 내려가고(미리 보인 하위 목록, OST 곡) 아니면 CLR로 올라간다(사슬은 `chain_of`, 원본 CLR 표 0x47350과 같다). 폭 512처럼 내용 칸이 300dp보다 좁으면 도움말 색인을 감추고 머리 띠 ◀▶로 넘긴다. 폭 < 400(원작 대조 시험)은 메인에서 레일만, 그 아래에서 패널만 보인다.
- 도움말은 원작의 6줄 쪽 대신 【항목】별로 묶어 보인다(사용자 결정). 옵션의 도움말과 타이틀 메인 메뉴(게임정보 › 도움말)가 같은 것을 본다(`restored/help.c`: 묶음, 문단, 지금 항목, 입력 / `ui/help.rcss`). 타이틀은 원본의 쪽 번호(W+0x15c)를 0에 묶고 `pend_dir`로 이 틱의 키를 받는다. 타이틀의 게임속으로(GOT 0x21c)도 같은 모듈로 ◈ 항목(시나리오, 일러스트, 사운드)별로 묶는다(이음새 표 `tight_intro`, 이름 목록은 쉼표로 `comma_intro`). 원본 글은 좁은 창 폭으로 손으로 끊겨 있어 문단으로 다시 잇는다(◈ 소제목, ☞ 항목, 빈 줄 문단). 끊긴 자리의 띄어쓰기는 폭으로 가를 수 없어 이 게임 글(FNV-1a 0xf80c1b62)은 붙여 쓸 줄 번호를 표로 둔다(`restored/ui_system.c` `help_tight`). 길면 글 상자를 넘긴다(`scroll` 속성: 끌기, 휠, ↑↓, 게임패드 오른쪽 스틱). ←→·색인으로 항목을 넘긴다.

## 터치와 게임패드

입력은 원본 코드가 그대로 받는다. 터치와 게임패드는 모두 원본 키로 바꿔 넘긴다.

- 터치로 목록의 먼 줄을 누르면 호스트가 원본 키를 틱마다 하나씩 보내 커서를 옮기는데(`goal_step`), 그동안 선택 띠가 중간 줄을 훑어 누름·선택이 꼬여 보였다. 이동 동안에는 데이터를 반영한 뒤 그 목록의 `sel` 클래스를 목표 줄에만 두고(`host/ui.cpp` `hold_goal_view`), 끝나면 문서 값을 다시 읽혀 되돌린다. 그래서 선택 표시는 `sel` 클래스로 나타내야 한다(줄 안 커서 표시도 `.sel`을 따르게, 예: `ui/dialog_choice.rml`의 ▶). 시험: `ECPE_NAVLOG=1`이면 목표 이동의 매 단계(알린 커서, 목표, 보낸 키)가 로그에 남는다(지나침·되돌아옴 확인).
- 화면 패드는 플레이 장면에서만 보인다(`host/ui.cpp` `input_frame`의 `play`, `ui/pad.rml`이 바인딩). 타이틀 쪽 장면(0~6, 22, 23), 필드 메뉴(14), 게임 중 불러오기(18)에서는 문서가 바뀌는 빈 틱에도 기본 필드 패드를 띄우지 않는다. 패드가 새로 나타나거나 모양이 바뀔 때는 4프레임 이어진 뒤에 바꾸고 숨길 때는 바로 숨긴다(한 틱짜리 번쩍임 방지, 폰에서 발견).
- **메뉴는 문서를 직접 누른다**(크로노스 윙과 다르다). 문서 요소에 `key="ok|clear|star|..."`(그 키 한 번), `nav="<목록>" idx="<번호>"`(그 항목), `action="settings"`, 여러 단계 이동은 `pick`(래퍼가 `ui_pick`으로 받아 원본 키를 보낸다)을 단다(`host/ui.h` '터치' 절). 목록 항목은 누르면 그 항목으로 가서 바로 OK다(사용자 결정. 처음에는 "고른 뒤 다시 누르면 결정"이었다). 래퍼는 고를 수 있는 상태에서 매 틱 `ui_nav(이름, 커서, 개수, 이전 키, 다음 키, 플래그)`로 커서를 알린다. 호스트는 목표 번호까지 틱마다 원본 키를 하나씩 누르고 다음 틱의 커서로 확인한다. 원본은 틱마다 "이번 틱에 누른 키" 하나만 읽으므로(입력 객체 +0, 쓰기 `0x61a0`, 읽기 `0x61d4`, 틱 끝 지우기 `0x613c`) 터치로 만든 키는 대기열에서 틱마다 하나씩 나간다. 누르고 바로 떼도 그 틱에는 눌린 키로 읽힌다. 세로 목록은 끌면 한 칸씩 넘긴다.
- **키 안내는 장치를 따른다.** 문서는 `{{ 'ok' | key }}`로 이름표를 쓰고, 마지막에 쓴 장치(키보드, 터치, 패드)에 따라 Enter/Esc/Z…, OK/CLR(터치에서는 감추고 안내 쌍 `.kb` 전체가 버튼), A/B/X/Y…(맵핑을 따른다)로 바뀐다. 장치에 따라 문서 body에 `touch`/`pad` 클래스가 붙는다.
- **화면 패드**(`ui/pad.rml`, `ui/ctl.rcss`)는 필드 이동용이다. 방향(가운데에서 본 각도로 정하고 손가락을 떼지 않고 옮길 수 있다. 방향을 떼면 아직 눌린 방향을 다시 눌러 이어 준다: 원본 입력 객체가 뗄 때도 +8에 키를 적어 걷기가 끊기던 문제, `main.c` send_key), OK, 메뉴(CLEAR), 지도(#), 비행정일 때 이착륙(0, 조건은 HUD `0x12b18`과 같다), 설정. 보이는 문서에 누를 것이 있으면 숨는다. 전투 내내 OK·취소(`UI_PAD_KEYS`, 사용자 결정), 원본이 그리는 선택(전투 대상 화살표)은 래퍼가 `ui_pad(UI_PAD_DIR)`로 방향+OK+취소를 띄우고, 입력이 없는 연출은 `ui_pad(UI_PAD_NONE)`. 게임패드로 조작하면 숨고 터치하면 다시 나온다. Android는 기본으로 켜지고, 데스크톱은 `--touch`나 설정에서 켠다.
- **게임패드**(`host/gamepad.c`, 크로노스 윙에서 가져옴): 왼쪽 스틱·D패드 이동, A 확인, B 취소(=CLEAR, 필드에서는 메뉴), START 메뉴, X `*`(아이템·핫슬롯), Y `#`(지도·메뉴 닫기), LB `0`, RB `7`, LT `1`, RT `3`, L3 `6`, R3 `9`, BACK 조작 설정(필드 메뉴 틀이 떠 있으면 LB/RB는 레일, LT/RT는 캐릭터이고, 장비 해제·핫슬롯 지우기의 `0`은 R3로 받는다). 맵핑은 설정 창의 `게임패드 키 설정`에서 바꾼다(다른 동작이 쓰던 버튼이면 맞바꾼다).
- **게임패드 전수 대응**(사용자 보고 2026-11-12: 패드로 닿지 않는 곳이 많고, 닿아도 안내가 없어 알 수 없다). 고친 방식은 넷이다.
  - *누르기 전용이던 것에 길을 냈다.* 환경설정 제목 옆 버튼 넷(조작 설정, 기타, 일러스트, 세이브 데이터)은 원작 줄 아래의 줄로 내렸다(`restored/cfgx.c`, 타이틀·필드 옵션 공용: 위아래로 가서 좌우로 값, 결정으로 「열기」). 스킬 「단축키」는 X(`*`), 장비 후보 상태의 「해제」「강화」도 그 키로(틀의 `ext_shell_key`가 버튼 띠의 fn 버튼을 키로 받는다), 프리미엄 상점 MAX는 Y(`#`), 상점 분류 탭은 LB/RB(`shoulder`).

  - *안내를 붙였다.* 필드 오른쪽 아래 「A 조사·대화 / B 메뉴」, 지도 이름 앞 Y, 퀵세이브 RS, 필드 메뉴 레일 「LB RB 메뉴 이동」(키보드 Tab), 캐릭터 띠 ◀▶의 LT/RT(키보드 `[ ]`), 버튼 띠의 방향 안내(`fm_bar_hint`: "←→ 분류" 등), 타이틀 메뉴의 방향 안내(`d.hint`), 대사 ▼ 옆 결정 키, 전투 명령의 「결정」과 대상 고르기의 「↑↓←→ 대상 / 결정 / 취소」, 상점 「나가기」의 B. 어깨 버튼·START처럼 원본 키로 가릴 수 없는 이름표는 `{{ 'lb' | padkey }}`(패드일 때만 글), 패드·키보드 전용 표시는 `.ponly`·`.konly`(base.rcss).
  - *설정 창*(조작 설정, 게임패드 키 설정, 기타 설정, 세이브 데이터)은 전부터 방향·A·B로 움직였지만 안내가 없었다. 창 아래에 「↑↓ 이동 / ←→ 값 / A 선택 / B 닫기」(키보드면 Enter/Esc)를 둔다(모델 값 `src`, `pad_ok`, `pad_back`).
  - 타이틀 메인 메뉴는 패드면 처음부터 첫 줄에 커서를 둔다(전에는 첫 입력이 커서만 꺼냈다).

- **자동 전투·전투 2배속**(사용자 요청 2026-11-10; `restored/autobattle.c`, `ui/battle_auto.rml`): 전투 화면 오른쪽 위 AUTO·x2 버튼, 키보드 R(자동 전투)·F(2배속)(원작 그리기 F2에서도 동작, 알림이 뜬다), 게임패드는 키 설정에서 붙인다(기본 없음), 상태는 `ui.ini`(`autobattle`, `fastbattle`). 자동 전투는 전투 틱 `0x109f0`을 감싸 명령 차례(ATB 찬 멤버의 `M+0x60`이 4~9, 행동 중 아님)마다 파티 상태를 보고 행동을 하나 정해(`make_plan`) 원본 키를 `ui_key_tap`으로 넣는다. 우선순위: 1) 전투불능 아군 + 부활 아이템(효과 `0x10`: 홀리워터, 둘 이상이면 전체 대상 미라클포션 먼저), 2) 아군 HP가 `LOW_HP_PCT`(35%) 이하이면 회복 아이템(가진 것 중 필요한 만큼을 채우는 가장 낮은 등급, 못 채우면 가장 많이 채우는 것; 전체 대상 회복은 여럿이 낮을 때 먼저, 지금 데이터에는 없다), 3) MG 가득이면 MP가 충분한 필살기들 가운데 무작위 하나(MP 모자란 것은 후보에서 빼고, 없으면 기본 공격; 필살 목록에서 ↑↓로 그 칸까지 옮겨 OK)(마지막 적이 `SAVE_SPECIAL_ENEMY_PCT` 이하로 거의 죽었으면 아낀다), 4) 기본 공격 → 가장 HP 낮은 적. 기준값은 코드 맨 위 상수. 아이템은 한 차례에 하나, 같은 대상에 연달아 쓰지 않는다(HP `CRIT_HP_PCT` 이하는 예외). 마나 아이템은 쓰지 않는다(MP 스킬은 고르지 않는다). 아이템은 `*` 키로 연 전투 아이템 창에서 분류 탭(↑↓)·칸(←→)으로 찾는다: 핫슬롯 탭 밖의 분류 탭에도 가진 것 전부가 있어 핫슬롯 등록과 무관하다. 아이템 레코드: `+0x14` 효과(0x10 부활, 0x15 HP 고정, 0x16 HP %, 0x17·0x18 MP), `+0x1a` 값; 전체 대상은 설명이 "전체"로 시작하는지로 안다. 한 단계가 `ITEM_STAGE_TRIES`번 키로도 안 되면 포기하고 기본 공격. 그 차례가 시작된 뒤 사람이 키를 넣으면(`ui_human_ms`) 그 차례는 사람 몫이다. 결과 화면은 0.9초 뒤부터 0.7초마다 OK. 부활석 창(`ext_revive_asking`)이 떠 있는 동안은 키를 넣지 않는다. 2배속은 전투 장면에서만 게임 시계(api 28, `game_time_ms`)를 2배로 흐르게 하고 타이머 간격을 반으로 줄인다(`host/runtime.c`). 결과·패배 화면은 원래 속도. 시험 확인: 틱 22/s → 44/s, ATB 증가도 정확히 2배.

## 원본과 다른 점

- 첫 실행은 원작대로 "속도최적화" 뒤 `gopt.sav`를 남기고 재시작을 요청하며 끝난다. 이 종료만 프로세스 안에서 게임을 다시 시작해 이어 간다(`main.c`).
- `GetFreeMemory`는 4MB를 돌려준다. startClet은 이 값(최대 0x164000)만큼 게임 힙을 잡는데, WIE의 1MB로는 첫 집을 나갈 때 리소스 할당이 실패해 죽는다.
- 글자: 게임은 플랫폼 글꼴(`DrawString`)을 쓴다. WIE와 같은 neodgm.ttf(OFL)를 같은 방식(ab_glyph 10pt)으로 빌드 때 표로 만든다(`work/tools/glyphdump`, `host/font.c`). 대사 프레임이 WIE와 픽셀까지 같다. 다만 neodgm에는 KS X 1001 기호·한자 일부(∼, ♡, ★ 등 약 4,900자)가 없어 WIE와 원래 빌드는 네모를 그렸다. 원래 폰은 KS X 1001을 다 그렸으므로 그 글자만 Galmuri9에서 가져온다(대사 "와.와∼짝.짝.짝∼" 등).
- 소리: 게임은 res.gmf 안에 압축된 MMF를 풀어 넘긴다. 실행 중에 smaf-player로 바꿔(`work/tools/smafev`, 정적 라이브러리) TinySoundFont로 합성한다.
- 배경음과 효과음을 함께 낸다(`restored/sound.c`). 원본은 클립 하나로 모든 소리를 내서 효과음(번호 0xf~0x15)마다 배경음을 끄고 효과음 뒤 다시 요청했다(필드에서 걸을 때마다 배경음이 처음부터 다시 나왔다). 크로노스 윙처럼 효과음 처리 안의 정지는 배경음에 적용하지 않고, MIDI 효과음(0x11)은 따로 둔 합성기로 낸다. 효과음이 지금 소리일 때의 정지 뒤 약 1초 안에 배경음 요청이 없으면 그때 배경음을 끈다(원본의 무음 연출).
- 네트워크는 모두 실패를 돌려준다.

- 맵: 읽기 `0x387c8`(전투 맵, `0x1b1d0`에서), 그리기 `0x3892c`(전투 `0x1bcd4`, 필드 `0x2839c`에서). 타일 `0x2e0a8`/`0x2e2ac`.
- 갱신 격자: 만들기 `0x205c4`, 표시 `0x20680`, 검사 `0x2077c`, 넘기기/지우기 `0x20764`/`0x207b0`, 전부 표시 `0x207c8`.
- 필드 그리기 `0x2ee2c`, 뒷배경 `0x381a0`(투명 검사 `0x2ed24`, 타일 `0x2e068`), 필드 보기 사각형은 게임 객체 `+0x568`.
- 소리 관리자(`[[game]+0x3c]`, 만들기 `0xad04`): 재생 요청 `0x11aec(game, 번호, 1, 플래그)` → `0xae60`, 실제 재생 `0xadf0`(`0xaeb0` 틱), 정지 `0x11b90` → `0xaedc`. 소리 번호 0~0xe 배경음·징글, 0xf~0x15 효과음, 0x16~0x1a 이벤트 음악. 소리 표 `game+0x544`(16바이트: 번호, 플래그(0x100 반복), 크기, 데이터), 읽기 `0x1197c`.
- 필드 장면 그리기 `0xc958`(상태별 분기), 연출 뒷배경 `0x38418`(`0xcdf0`에서), 맵 밖 여백 칠하기 `0x2f7c4`(`0x2ec68`에서), 위 레이어 `0x2f170`, 미니맵 `0x2f06c`.
- 필드 카메라: 필드 객체 `+0x18`/`+0x1c`, 맵 픽셀 크기 `+0x78`/`+0x7c`. 가운데 놓기 `0x2f3c0`, 놓고 가두기 `0x2f3e4`, 가두기 `0x2ea20`, 따라가기 `0x113ac`.
- 화면 폭은 gfx 객체 `+0xdc`의 클립 사각형(x, y, w, h)에 있다.

## 시험

- `work/tools/nshot.sh <출력> [인자] -- [키...]`: 임시 저장 폴더로 띄워 키마다 화면을 남긴다. `work/tools/shot.sh`는 같은 일을 WIE로 한다(대조용).
- `ECPE_FRAMELOG=<폴더>`: 프레임 해시와 raw(WIE `WIE_FRAMELOG`와 같은 형식). `ECPE_SCRIPT`, `ECPE_TRACE`, `ECPE_RESLOG`는 진단용. `ECPE_SOUNDDUMP=<파일>`은 최종 믹스를 float 스테레오 raw(장치 주파수, 로그에 적힘)로 남긴다.
- `work/tools/nctl.sh start <폴더> [인자]`, `nctl.sh <폴더> <명령...>`, `nctl.sh stop <폴더>`: 띄워 둔 채 한 단계씩 조작하고 `<폴더>/now.png`를 남긴다. `key <이름> [ms]`로 누르는 시간을 정한다.
- `work/tools/tobattle.sh <폴더> [인자]`: 저장 사본을 불러와 첫 필드를 오가며 전투까지 간다. `fight.sh <폴더>`는 전투 중이면 이길 때까지 OK를 누른다.
- ctrl 파일의 `poison`(nctl.sh `poison`): 화면 버퍼를 자홍색으로 덮는다. 그 뒤에도 자홍색이 남는 곳은 게임이 다시 그리지 않는 곳이다. 필드는 매 프레임 다 그려 바로 사라지고, 전투는 갱신 격자에 표시된 칸만 돌아온다(240 폭 원본도 같다).
- ctrl 파일의 `framelog <폴더>`/`framelog off`: 그 사이 프레임만 남긴다(`ECPE_FRAMELOG`와 같은 형식).
- ctrl 파일의 `memdump <파일>`: 게스트 메모리(0x100000부터)를 파일로 남긴다.
- 대사: `script.bin`은 "1001" 묶음이고 항목(표: 12바이트씩, 첫 워드가 오프셋)마다 +16에서 LZMA1 raw(속성 바이트 1 + 사전 크기 4, 이어서 데이터)로 풀린다. 글자는 CP949다.
- `make TRFLAGS=-DTRACE_PC`: 메모리 오류 때 pc를 남긴다. `TRFLAGS="-DTRACE_PC -DWATCH_VAL=506"`이면 그 값(과 절반)을 읽는 pc를 처음 한 번씩 남긴다. 화면 폭을 506처럼 드문 값으로 띄워 폭을 쓰는 코드를 찾는 데 썼다.

## Android

```bash
make android   # build/android/ecpe.apk (arm64-v8a, android/ecpe.keystore 서명). adb install -r build/android/ecpe.apk
```

Gradle 없이 NDK와 build-tools로 만든다(`android/build.sh`, 크로노스 윙과 같은 구조). SDL3·RmlUi·FreeType 소스는 `build/deps`의 것을 쓴다(없으면 `make android`가 `./deps.sh android`로 받는다). 다른 곳에 받아 두었으면 `CW=<그 native 폴더>`. SDK·NDK·JDK는 `ANDROID_HOME`, `ANDROID_NDK_HOME`, `JAVA_HOME`(없으면 Homebrew 자리).

- 앱 이름 "에픽크로니클 PE", 패키지 `local.ecpe`, 가로 고정(`sensorLandscape`), 전체화면. 첫 실행 때 APK의 `game.pak`(`android/mkpak.py`)을 앱 내부 저장소 `data/`에 푼다(`host/android_data.c`). 팩 구조가 `game/`, `font.gly`, `ui/`, `1mgm.sf2`라 `main.c`의 `game_dir/../font.gly` 같은 경로가 그대로 맞는다. 세이브는 `SDL_GetPrefPath`의 다른 폴더다.
- 소리 변환 Rust 라이브러리(`work/tools/smafev`)는 `aarch64-linux-android`로 교차 빌드한다(`rustup target add aarch64-linux-android`가 한 번 필요하다. 크레이트는 `--offline`).
- NDK에는 iconv가 없어 UI의 CP949→UTF-8은 표 변환(`host/cp949.c`, 표 `host/cp949_table.c`)이다. 맥에서도 같은 코드를 쓴다. 표는 macOS iconv에서 `android/gen_cp949.py`로 만들었고, 무작위 입력 30만 개로 iconv 결과와 바이트까지 같음을 확인했다(파이썬 `cp949` codec은 0xA2E8 한 글자가 달라 쓰지 않았다).
- 서명 키 `android/ecpe.keystore`는 처음 빌드 때 만들어지며 git에 올리지 않는다(`.gitignore`). 잃으면 설치된 앱을 지워야 업데이트된다.
- 아이콘은 타이틀 화면 프레임(맥 빌드 `ECPE_FRAMELOG`, `ECPE_SCRIPT`)에서 `android/mkicon.py`로 만든다. 원본 파생물이라 `build/android/res`에만 있다. 통신사 로고, 등급 표시, 버전 글자는 흰 줄로 덮는다.
- 크로노스 윙과 달리 `patch_activity.py`는 두지 않았다. 세이브 내보내기용 파일 창을 쓰지 않아서다. `patch_manifest.py`(configChanges 보정)는 같다. `ECPE_DEBUGGABLE=1`로 빌드하면 run-as 진단용이다.
- 배포용 경로 지우기: 실행 파일에 빌드한 맥의 경로(사용자 이름)가 남지 않게 컴파일에 `-ffile-prefix-map=$HOME/=`, Rust에 `--remap-path-prefix`를 준다. 크로노스 윙의 Android용 RmlUi·FreeType에는 경로가 남아 있어 같은 소스로 `build/android/deps`에 따로 빌드해 쓴다(`build.sh` 앞부분). Windows는 `Makefile`의 `WMAP`·`WRUSTFLAGS`(크로노스 윙의 Windows용 라이브러리는 이미 깨끗하다). 확인은 APK·zip을 풀어 사용자 이름을 찾아 본다.
- 버전은 `AndroidManifest.xml`의 versionCode·versionName(1.1/2부터). 업데이트를 나눠 줄 때는 versionCode를 올린다.
- 로그: stderr는 logcat 태그 `ecpe`로 나온다(`android_data.c`의 constructor). `adb logcat -s ecpe SDL`.

## Windows

```bash
make windows   # build/win(실행 파일 ecpe.exe)과 옮기기용 build/ecpe-win.zip. 폴더 통째로 옮겨 ecpe.exe를 실행한다
```

mingw-w64(`x86_64-w64-mingw32-gcc`, Homebrew)로 교차 빌드한다(크로노스 윙 `make windows`와 같은 구조). SDL3 mingw 개발 패키지와 Windows용 RmlUi/FreeType은 `build/deps/mingw`, `build/deps/win/install`(없으면 `make windows`가 `./deps.sh win`으로 만든다). 다른 곳이면 `WSDL=`, `WRML=`.

- 폴더 구성: `ecpe.exe`, `SDL3.dll`, `libwinpthread-1.dll`, `game/`(jar에서 푼 데이터, `client.bin`), `font.gly`, `ui/`, `1mgm.sf2`, 글꼴·사운드폰트 고지. `main.c`의 `game_dir/../font.gly` 경로가 맥 빌드와 같다. 세이브는 `SDL_GetPrefPath` → `%APPDATA%\ecpe\save`.
- 소리 변환 Rust 라이브러리는 `x86_64-pc-windows-gnu`로 교차 빌드한다(`rustup target add x86_64-pc-windows-gnu` 한 번). 링크에 `ws2_32 userenv bcrypt ntdll`이 든다.
- 매니페스트(`windows/ecpe.manifest`)로 코드 페이지를 UTF-8로 둬 한글 경로의 `fopen`이 통하고, DPI는 PerMonitorV2다. 게스트 메모리는 `VirtualAlloc` 예약(`host/memory.c`).
- 아이콘은 Android와 같은 그림이다. `windows/mkico.sh`가 맥 빌드로 타이틀 프레임을 받아 `android/mkicon.py`로 자른 뒤 16~256px PNG를 ICO에 담는다(`build/ecpe.ico`, 원본 파생물).
- 화면 모드(데스크톱 공통, 원작에 없다): 환경설정의 원작 줄 아래 「화면 전체화면/창」 줄(타이틀 환경설정 `restored/ui_title.c` `opt_disp_key`, 인게임 옵션 환경설정 `restored/ui_system.c` `cfg_disp` — 둘 다 원본 커서로 닿지 않는 가상 줄이고 위아래가 원작 줄과 한 고리로 돈다), F11, Alt+Enter. 바로 적용되고 `ui.ini`의 `fullscreen`과 창 크기 `window <폭> <높이>`에 남아 다음 실행이 그 모드·크기로 뜬다(`ui_peek_display`로 창을 만들기 전에 읽는다). `--windowed`로 띄운 실행은 저장된 모드를 바꾸지 않는다. Android와 헤드리스에는 줄이 없다.
- 이 맥에는 Windows나 wine이 없어 실행은 확인하지 못했다(빌드와 의존 DLL 목록만 확인).

## 귀환 주문서와 조우율 향(restored/warp.c, restored/incense.c, ui/warp.rml)

원작에 없는 소모품(items_ext.h의 249 귀환 주문서, 250 정적의 향, 251 유혹의 향). 아이템 창에서 '사용'하면 ext_use가 처리기를 부른다.

- **맵 전환 구조**: 이동 대상은 G+0x2d(맵 번호), +0x2e(a), +0x2f(b)이고 스크립트가 [0xc1/0x3e 대상] → [0x54 주인공 위치(px)] → [0x49 맵 읽기(0x3c294 → 0xd044)] 순으로 쓴다. 귀환은 같은 길을 탄다(주인공 위치를 미리 써 놓고 0x3c294를 부른다). 자세한 내용은 warp.c 머리말.
- **마을 허용 목록**(warp.c 위 `TOWNS` 표, 14곳): 여관 서비스가 있는 8곳(프리빌, 수도 아멜고, 호스스피릿, 트리튼, 매그파이마운트, 라바티마을, 쥬얼힐즈, 포스웰), 제라노스 성, 사용자가 추가한 5곳(가디언마을, 뉴러키우드, 페어리랜드, 엘프랜드, 호스우드; 뒤의 셋은 숲·야영지 지역). 마을마다 입구 (맵, a, b, 주인공 px)를 스크립트의 문 이동 묶음에서 뽑았고 모두 실제로 이동해 확인했다. 엘프랜드·호스우드는 맵의 지역 이름이 비어 있어 이동할 때 이름을 미리 쓴다(지역 이름 띠는 안 뜬다). 지역 이름(G+0x4dc)이 표에 있고 저장 가능한 자유 상태면 '가 봄'으로 기록한다(조우 여부는 보지 않는다).
- **미리 채우기**(불러온 뒤 처음 한 번, ext `warp.seeded`; warp.c `SEEDS` 표): 이벤트 트리거 액터(vtable 0x14da10)는 밟아서 실행되면 자기 플래그를 배열 A(G+0x38)에 켠다(명령 0x73). 배열 A를 켜는 곳은 이것과 스크립트 0xab(번호 320) 뿐이고 끄는 곳이 없어서, 마을 안 트리거의 플래그가 켜져 있으면 그 마을에 선 적이 있다. 14곳 모두 맵·구역별 트리거 플래그를 `WARP_ASCAN`(맵마다 실제로 이동해 액터를 읽는 조사용 환경 변수)으로 뽑아 표에 넣었다. 보조 근거로 저장 사본의 플레이 시각 순서(아이언우드 < 수도 아멜고 < 제라노스 성)에 맞춰 성 안 사건 플래그(124 등)가 켜져 있으면 수도 아멜고도 지난 것으로 본다. 84·86·130·150·151·155 비트는 근거를 못 찾아 쓰지 않았다. 결과: 슬롯1 = 제라노스 성 + 수도 아멜고, 슬롯2 = 제라노스 성(플래그 153) + 수도 아멜고(현재), b512(아이언우드) = 없음. `WARP_TESTFLAGS="66,69"`로 비트를 켜 보고 나머지 마을 규칙의 동작도 확인했다(실제 저장 사본이 없어 플래그를 억지로 켠 시험).
- **조우율**: 걸음 카운터 0x1afac(E, 1)의 증가량을 곱한다(정적 ×0.25, 유혹 ×3, 지속 300걸음, 같은 향이면 +300 최대 900, 다른 향이면 교체). 원작은 걸음마다 카운터를 올려 최소 걸음(E+0x18, 첫 필드 55)에 닿으면 조우한다(난수 구간은 첫 틱에만 더해져 실제로는 늘 최소 걸음이다).
- 시험용 환경 변수: `WARP_DBG=1`(기록·이동 로그), `WARP_CMD=<파일>`("맵 a b [px py]"를 적으면 필드 틱에서 이동), `INCENSE_LOG=1|2`(조우 간격 로그, 2면 조우를 막는다), `INCENSE_SIM=<걸음수>`(향 없음/정적/유혹의 조우 횟수를 실제 0x1aee8로 잰다), `ECPE_EXT_GIVE="249:3,250:3,251:3"`.
