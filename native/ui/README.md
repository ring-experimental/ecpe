# 메뉴 현대화(RmlUi) 작업 안내

원작 메뉴는 240×320 화면에 맞춘 작은 창이다. 넓은 화면(높이 320dp, 폭 240~640dp, 보통 568dp)에 맞춰 RmlUi로 다시 짠다.
입력과 상태 변화는 원본 코드가 그대로 처리하고, **그리기만** 바꾼다. 원본 그리기 함수를 감싸 그 틱의 값을 문서에 넘긴다.

## 구조

- `host/ui.h`: 게임 쪽 C API(읽고 시작한다). `ui_begin("문서")` ~ `ui_end()` 사이에 `ui_int/ui_str/ui_list/ui_item/...`으로 값을 채운다.
- `ui/<문서>.rml`: 화면. `<body data-model="<문서>">`이고 값은 `{{d.키}}`, `data-for="it : d.items"`, `data-class-sel="it_index == d.cursor"`, `data-if`, `data-style-width="d.pct + '%'"`, `data-attr-src="d.icon"`로 읽는다.
- `ui/base.rcss`: 공통 부품(창 `.panel`, 제목 띠 `.title`, 목록 `.row`/`.sel`, 탭, 게이지, 키 안내 `.keys`, 여닫는 움직임 `.pop`). **고치지 않는다.** 화면만의 배치는 문서의 `<style>`에, 한 영역의 여러 문서가 같이 쓰는 것은 `ui/<영역>.rcss`에 둔다. `ui/_gallery.rml`이 부품 견본이다.
- `restored/ui_<영역>.c`: 감싼 함수들. `restored/list.d/<영역>.txt`에 `<오프셋> ui_<영역>.c wrap` 줄을 적는다(`wrap`이면 원본이 `orig_f_<오프셋>`으로 남는다).

```c
#include "restored.h"
void orig_f_31b18(cpu_t *c);
void f_31b18(cpu_t *c) {
    if (!ui_modern()) { orig_f_31b18(c); return; }   // 원작 그리기(F2, --classic, ctrl `ui classic`)도 그대로 살아 있어야 한다
    cpu_t saved = *c; (void)saved;                     // 원본을 부른 뒤에도 레지스터가 필요하면 미리 챙긴다
    uint32_t self = c->r[0];
    ui_begin("item");
    ui_int("cursor", (int)R32_(c, self + 0x..));
    ui_list("items");
    for (...) { ui_item(); ui_str("name", gstr(name_addr)); ui_int("count", n); ui_close(); }
    ui_close();
    ui_end();
}
```

게스트 메모리는 `R32_(c, addr)`/`R16_`/`R8_`, 문자열은 `gstr(addr)`(CP949), 게스트 함수 호출은 `CALL(0x100000 + 오프셋, 인자...)`다(`restored/camera.c`, `battle.c` 참고).

## 규칙

1. 원본 그리기 함수가 하던 **부수 효과**(애니메이션 카운터, 리소스 읽기, 상태 전이)가 있으면 지켜야 한다. 가장 안전한 방법은 원본을 그대로 부르되 화면만 버리는 것이다: `ui_scratch_begin(); orig_f_xxx(c); ... ui_scratch_end();`. 이 사이에 원본이 `DrawString`으로 그린 글은 `ui_cap_text()`로 받을 수 있어, 구조체를 다 풀지 않아도 원본이 만든 글(조합된 수치, 설명문)을 그대로 쓸 수 있다. 다만 **어느 글이 무엇인지는 좌표가 아니라 값의 출처로 정하는 편이 낫다**(구조체를 읽을 수 있으면 읽는다).
2. 초상화·아이콘 같은 그림은 `ui_scratch_begin()` 뒤 원본 스프라이트 그리기를 불러 `ui_sprite()`로 뗀다(ui.h 설명). 창 바탕 위에 그려진 것을 통째로 떼면 바탕색이 묻으니, 그림 하나만 따로 그리게 해서 뗀다.
3. `ui_begin~ui_end`를 부른 틱에만 문서가 보인다. 원본이 매 틱 다시 그리지 않는 화면(한 번 그리고 멈추는 화면)은 틱 함수 쪽에서 부르거나, 그 화면이 떠 있는지 상태로 판정해 매 틱 채운다.
4. 원본 창이 차지하던 자리를 원본이 따로 지우거나 칠한다면(바탕 사각형, 테두리) 그것도 함께 막는다. 반대로 원본 그리기를 막아서 **게임 화면에 지난 프레임이 남지 않는지** 확인한다(`poison` 명령: 화면을 자홍으로 덮어 다시 안 그려지는 곳을 찾는다).
5. 원작에 있던 정보는 하나도 빼지 않는다(값, 수량, 설명, 키 안내, 선택 상태, 비활성 표시, 스크롤 위치). 넓어진 화면에는 원작이 좁아서 나눠 보이던 정보를 한 화면에 함께 보여도 좋다(예: 목록 + 설명 + 캐릭터 상태). 단, 원본 상태에 없는 값을 지어내지 않는다.
6. 폭 240, 320, 568, 640에서 모두 깨지지 않아야 한다. 폭은 `%`/flex로 잡고, 좁을 때 줄이는 배치는 `ui_int("narrow", ui_screen_w() < 400)` 같은 값을 넘겨 `data-class-narrow`로 바꾼다(RCSS 미디어 쿼리도 된다: `@media (max-width: 400dp)`).
7. 글꼴은 Neo둥근모 하나다. 크기는 `12dp`(본문), `10dp`(보조), `16dp`(강조)만 쓴다.
8. 다른 영역의 파일, `host/`, `base.rcss`, `list.txt`는 고치지 않는다. 꼭 필요한 호스트 기능이 있으면 만들지 말고 최종 보고에 적는다.
9. 새 배치에서 고르는 방향이 원본 키 방향과 달라지면(세로 목록을 원본은 좌우로 넘기는 등) 그 틱에 `ui_key_alias_v2h()`/`ui_key_alias_h2v()`(또는 `ui_key_alias(from, to)`)를 부르고, 키 안내도 새 배치의 방향으로 적는다.
10. 주석과 문서는 한국어로, 왜 그렇게 했는지를 적는다. 주소는 파일 오프셋(게스트 주소는 +0x100000)으로 적는다.
11. 터치·게임패드(`host/ui.h` '터치' 절): 원본 키로 하던 조작은 모두 문서를 눌러서도 되게 한다. 고르는 목록은 그 상태에서 매 틱 `ui_nav`로 커서를 알리고(이전/다음은 별칭 전 원본 키, 번호는 전체 목록 기준, 빈 칸은 -1) 줄에 `nav`/`data-attr-idx`를 단다. 누르면 바로 결정하는 목록은 `UI_NAV_ACT`. 키 기능(OK, CLR, *, #, 숫자)과 좌우 값 조절은 `key` 속성 버튼으로 둔다. 키 글자는 `{{ 'ok' | key }}`로 써서 장치별 이름표가 나오게 하고, 안내 쌍은 `.kb`로 감싼다(터치에서는 버튼이 된다). "아무 키나"·대사 넘기기는 `<div class="tapall" key="ok">`. 입력이 없는 연출 동안 문서가 떠 있으면 `ui_pad(UI_PAD_NONE)`, 원본이 그리는 선택은 `ui_pad(UI_PAD_DIR)`. 터치에서 누를 곳이 작으면 `body.touch` 규칙으로 키운다. 시험은 `nctl.sh`의 `source touch|pad|keyboard`, `tap '<선택자>'`, `fing <x> <y>`.

12. 게임패드(사용자 보고 2026-11-12): **`pick`/`action`만 단 요소는 패드로 닿지 않는다.** 새로 두면 셋 중 하나로 길을 낸다 — 래퍼가 원본 키로 받기(그 화면이 안 쓰는 `*`·`#`·숫자), 목록 줄로 넣기(환경설정의 여는 줄 `restored/cfgx.c`), 남는 버튼 빌리기 `padhot="<동작 id>"`(`host/ui.h`). 그리고 **길이 있으면 반드시 이름표를 보인다**: 원본 키는 `{{ 'star' | key }}`, 어깨 버튼·START처럼 원본 키로 가릴 수 없는 것은 `{{ 'lb' | padkey }}`(lb rb lt rt, 동작 id)를 `.ponly`로 감싸고, 키보드 전용 글쇠(Tab, F5)는 `.konly`. 방향 안내는 필드 메뉴 틀이면 `fm_bar_hint("←→ 분류")`, 그 밖은 문서의 `.keys .nav`.

## 세로 목록 `<vlist>`

고르는 세로 목록은 모두 `<vlist>` 부품으로 쓴다. 호스트(`host/ui_vlist.cpp`)가 문서를 읽을 때 보통 RML로 펼치고 `ui/vlist.rcss`를 건다.
줄 높이·선택 띠·스크롤바·빈 목록 글·터치 크기가 모든 화면에서 같아지고, 아래 조작이 목록마다 따로 짜지 않아도 붙는다.
문서 `<style>`에서 `.vrow` 모양을 다시 정하지 않는다(화면만의 열은 안쪽 내용으로 넣고 그 클래스만 꾸민다).

```xml
<vlist for="it : d.items" nav="items" idx="it.i" sel="it.sel" icon="it.icon" label="it.name" value="'×' + it.count"
       scroll="ilist" empty="d.total == 0" empty-text="가진 아이템이 없습니다"/>
<vlist for="h : d.hsections" pick="help" idx="h.i" sel="h.cur" label="h.t" size="s"/>   <!-- icon이 없으면 글만 -->
```

| 속성 | 뜻 |
|---|---|
| `for` (필수) | `data-for` 식(`it : d.items`). 줄 번호는 `it_index`. |
| `label` (필수) | 이름 식. |
| `icon` | 아이콘 그림 식(`ui_sprite`로 뗀 이름). **이 줄의 값이 빈 글이면 아이콘 칸도 생기지 않는다**(글만). |
| `sub` | 이름 아래 작은 줄(보통 `size="l"`과 함께). |
| `value`, `value-class` | 오른쪽 값(수량, 가격, MP)과 그 색 클래스(`gold`, `good` …). |
| `lead` | 이름 앞의 짧은 표(번호, 단축키). |
| `badge` | 이름 뒤의 작은 딱지(빈 글이면 안 보인다: `E`, `NEW`, `+3`). |
| `nav` / `pick`, `idx` | 터치·마우스로 고르기(ui.h). `idx`는 식(`it.i`, `it_index`). `key`는 줄을 누르면 보낼 키 식. |
| `sel`, `idle`, `dis`, `off` | 고른 줄 / 포커스가 다른 창일 때의 고른 줄 / 쓸 수 없는 줄(흐림) / 감춘 줄. |
| `row-class` | 줄에 더 붙일 `data-class-...` 속성들(그대로 옮긴다, 예: `row-class='data-class-r1="it.rar == 1"'`). |
| `scroll` | 길어지는 목록은 꼭 단다. 상자를 넘기고, 커서 줄이 보이게 호스트가 넘긴다. |
| `empty`, `empty-text` | 빈 목록일 때 보일 조건과 글. |
| `size` | `s` 작은 줄(14dp, 10dp 글), `m` 보통(18dp, 기본), `l` 두 줄 카드(30dp). |
| `id`, `class`, `if`, `box-class` | 상자의 id·클래스·`data-if`·그 밖의 속성. |

`empty-text`에는 `{{d.empty}}`처럼 값도 쓸 수 있다. `row-class`/`box-class` 안에 글 상수가 필요하면 바깥을 작은따옴표로 감싸고 안의 작은따옴표는 `&#39;`로 쓴다
(`row-class='data-attr-nav="d.act ? &#39;menu&#39; : &#39;&#39;"'`). 주석과 `<style>` 안의 "<vlist" 글자는 펼치지 않는다.
pick 줄(자체 화면)도 한 줄 앞 미리 보이기(`ui_scroll_show`), PgUp/PgDn/Home/End, 마우스 올리기가 된다(고른 줄이 아닌 줄을 pick = 커서만 옮김).

`<vlist ...>안쪽</vlist>`로 쓰면 안쪽 내용이 이름(배지)과 값 사이에 들어간다(줄마다 더 보일 열이 있을 때). 펼친 결과는
`ECPE_VLIST_DUMP=1`로 띄우면 실행 로그에 나온다.

모든 `<vlist>`에 붙는 조작(다른 게임·플랫폼 지침을 따른 것, 근거는 각 줄):
- 키로 옮기면 **한 줄 앞을 미리 보인다**: 커서가 보이는 끝 줄에 닿기 전에 넘어가 다음 항목이 늘 보인다(Microsoft "Designing for Xbox and TV": 목록 끝의 포커스 줄도 보이는 자리 안에).
- **PgUp/PgDn**은 한 쪽(보이는 줄 수 - 1), **Home/End**는 처음·끝(Microsoft "Gamepad and remote control interactions"의 가속 표, Xbox 접근성 지침 112의 Sea of Thieves 예). 패드 LT/RT는 이 게임의 원본 1·3번 키라 쓰지 않는다.
- **마우스를 올리면 그 줄로 커서**가 가고 누르면 결정한다(Xbox 접근성 지침 112: 메뉴는 마우스·키보드·패드 어느 것으로도, Grounded PC 예). 손가락은 지금처럼 누르면 바로 결정.
- **끝에서 돌기**: 마지막 줄에서 아래(다음)를 새로 누르면 첫 줄로, 첫 줄에서 위는 마지막 줄로(Xbox 접근성 지침 112). 누르고 있는 동안은 원본의 반복이라 끝에서 멈춘다. 원본이 이미 도는 목록(`UI_NAV_WRAP`)은 원본에 맡긴다.
- **게임패드 LT/RT 쪽 넘기기, LB/RB 탭**(같은 지침의 Sea of Thieves 배치): **필드 메뉴 틀이 떠 있으면 틀이 이긴다**(아래 '필드 메뉴 틀': LB/RB 레일, LT/RT 캐릭터).
  그 밖의 화면은 그 버튼에 묶인 원본 키(LB 0, RB 7, LT 1, RT 3)를 쓰면(보이는 `key`/`hold`/`keyhint`) 원본 키가 이긴다.
  LB/RB가 누를 곳은 문서가 정한다: 보이는 요소에 `shoulder="prev|next"`를 단다(◀▶ 버튼 자체, 없으면 `<span class="shk" shoulder="next" key="right">`, pick도 된다).
  필드 메뉴 화면과 그 안의 자체 창(프리미엄 상점 포함)은 틀이 떠 있어 `shoulder`를 쓰지 않는다(상점 탭은 패드 X = `*`). 시험은 `nctl.sh <폴더> shoulder 0|1|2|3`.
- 터치 중이면 줄이 20dp로 커진다(Microsoft 10-foot 지침의 최소 32epx).

## 필드 메뉴 틀

사용자 결정(2026-11-11). 모드 1(필드에서 연 일반 메뉴)의 화면 0~7에 같은 틀을 둔다(`restored/fm_shell.c`·`fm_shell.h`, 문서 `ui/fm_shell.rml`,
스타일 `ui/fmshell.rcss`). 상점(화면 8, 판매 포함)과 타이틀 쪽 옵션(모드 2·3), 원작 그리기(F2)에는 틀이 없다.
없애려는 것은 두 가지다: 화면에 보이는데 OK로 한 번 '들어가야' 조작되는 단계(메인의 대상 선택, 장비의 칸→후보, 스킬의 분류→동작→목록),
상태마다 버튼 수가 달라 OK·취소 자리가 바뀌던 키 안내 띠. **원본 상태 기계는 그대로 두고 래퍼가 대신 몰아, 사용자에게는 보이는 구조만 남긴다.**

- **틀 문서**: 분배 `0x2faa4`(`ui_fmcore.c`)가 화면 그리기 앞에서 `fm_shell_emit`으로 채운다. `ui_below()`로 늘 다른 문서 아래에 깔린다
  (옵션 도움말처럼 키 처리 쪽에서 먼저 채우는 문서도 위에 온다). 화면이 바뀌어도 닫히지 않으므로 레일은 움직이지 않는다(`.pop`도 처음 한 번).
  - 왼쪽 **레일**(x 14~124, 좁으면 아이콘만 폭 30): 메뉴 7개 + 소지금·플레이 시간·장소. 열린 화면 줄은 금색 테두리(`.cur`), 홈에서는 키보드 커서 줄이 `.sel`.
    줄을 누르면(pick `rail`) 어느 화면·상태에서든 바로 그 화면으로 간다.
  - **캐릭터 띠**(스킬·장비·스테이터스 위, y 10~40): 칩(24×23 초상 + 이름 + LV, 좁으면 초상만)과 양 끝 ◀▶(pick `chip`, `charstep`).
    마지막으로 본 캐릭터를 기억해 세 화면 모두 그 캐릭터로 연다(없거나 파티에서 빠졌으면 첫 칸). 홈의 파티 카드(pick `hparty`)는 그 캐릭터의 스테이터스.
  - **틀 안의 자체 창**(장비 강화, 귀환 주문서, 망각의 물약, 프리미엄 상점): 레일 오른쪽 내용 자리에 뜨고(`fm_overlay_frame`이 `d.shell`을 적고
    아래 화면 문서를 `ui_hide`로 감춘다, 막은 `.fmarea`로 내용 자리만 덮는다) 고정 버튼 띠를 쓴다. 레일은 잠그지 않는다: 창이 떠 있어도 레일·홈 카드를
    누르면 각 창의 닫기(CLR과 같은 길, 소모·적용 없음)로 닫고(결과 카드·결과 띠도 함께 넘긴다) 바로 그 화면으로 간다. 레일의 '현재'는 그 창을 연 화면이다.
    강화는 틀의 캐릭터 띠(칩·`[ ]`·LT/RT)가 강화의 파티원을 바꾼다. 「이전」은 각 창의 CLR(결과 카드·확인 → 창 닫기 → 연 화면).
    원작 그리기(F2)에서는 틀이 없으므로 이 창들은 예전처럼 전체 화면이다.
- **화면 문서**: `fm_doc_frame(menu)`가 `d.shell`·`d.chars`를 적고, 문서는 body에 `data-class-shell`·`data-class-chars`를 달아
  `fmshell.rcss`가 `.screen`을 내용 자리(x 132~554, 위 10 또는 44, 아래 44)로 옮긴다. 틀이 바탕 막을 깔므로 화면은 `.dim`을 `!d.shell`일 때만 둔다.
- **동기 키 도우미 `fm_key_raw(menu, 게임 키)`**: 필드 메뉴 키 분배 `0x2fa60`을 지금 바로 부른다(이벤트는 게스트 메모리 0x20바이트에 `+0` 코드,
  `+2` 1, `+0xc` 1, 나머지 0. 0x61d4·0x6204가 읽는 꼴). 틀의 훅은 건너뛴다(재귀 막기). "CLR 몇 번 → 탭 → OK → 캐릭터 맞추기 → OK"를 그리기 전에
  한 틱 안에서 끝내 중간 화면이 보이지 않는다. 누름 처리는 메뉴 장면 틱 `0x109b8`의 원본 앞(`ext_shell_tick`)에서 한다. 레지스터를 덮으므로 부르는 쪽이 cpu를 챙긴다.
  효과음은 따로 막지 않는다: 요청 `0x11aec`는 소리 관리자의 '지금 소리' 칸을 덮어쓰고 두 틱 뒤에 한 번 재생하므로 한 틱의 여러 요청은 마지막 하나만 난다.
- **숨긴 단계**: 메인의 대상 선택은 키보드로 들어가도 같은 틱에 기억한 캐릭터로 마저 넘긴다(`ext_shell_after`). 스킬은 그리기 앞에서 목록 상태(동작 = 사용,
  봉인이면 정보)로 몰아 두고(`fm_skill_normalize`, 목록 커서는 기억해 되돌린다), 분류는 목록 위 가로 탭(pick `skcat`), 단축키는 버튼 띠의 「단축키」가
  목록 → 동작 '장착' → 3/6/9 대기까지 한 번에 간다. 아이템의 '설명' 단계(소비물품이 아닌 분류의 OK)는 없앴다(설명은 늘 보인다, 줄을 눌러도 고르기만).
  장비는 칸·후보를 어느 상태에서나 바로 누른다(칸 = 고르기, 고른 칸을 다시 = 후보로, 후보 = 그 자리에서 장착. 후보 줄마다 지금 장비와의 차이).
  스테이터스 GP는 되돌릴 수 없어 줄을 눌러서는 고르기만 하고 줄의 ▲(pick `gpup`)나 「GP 분배」로만 올린다.
- **「이전」(CLR) 규칙**(`ext_shell_key`): 보이는 구조에서 한 단계 위. 지금 화면에 팝업·대상 고르기·핫슬롯 등록·단축키 대기·메시지·장비 후보·
  전투파티의 고른 동료가 있으면 원본이 한 단계 닫고, 없으면 홈으로(숨긴 단계를 한 칸씩 거꾸로 걷지 않는다), 홈이면 메뉴를 닫는다.
  옵션은 `ui_system.c`의 키 래퍼(하위 화면 → 목록 → 홈)에 맡긴다. 키보드·패드·터치·마우스 오른쪽 버튼이 모두 같은 길(원본 CLR 키)이다.
- **고정 버튼 띠 `<fmbar/>`**: 호스트(`host/ui_vlist.cpp`)가 펼친다. 값은 화면 래퍼가 `fm_bar_begin` → `fm_bar_ex(칸, 이름, 쓸 수 있음, 원본 키, 함수, 키 이름표)`
  → `fm_bar_ok(이름, 쓸 수 있음)` → `fm_bar_emit(menu)`로 `d.bar`에 채운다(`ex` 4칸 고정, `ok`, `back` 각 `t`/`on`/`kl`).
  오른쪽 끝 「이전」(홈은 「닫기」)과 그 왼쪽 「결정」은 폭 84dp(좁으면 60)로 늘 같은 자리·크기이고, 쓸 수 없으면 흐려진다(누를 수 없음).
  왼쪽 보조 버튼은 화면 안에서 칸 수·순서가 고정이다. 누르면 pick `fmbar`(보조 0~3, 결정 8, 이전 9)로 틀이 받아 원본 키를 `ui_key_tap`으로 넣거나 함수를 부른다.
  키보드·패드에서는 버튼 안에 키 이름표(`| Enter`)를 붙이고 따로 키 안내 줄을 두지 않는다(터치와 좁은 화면은 이름만).
- **장치 배치**: 마우스는 올리면 커서(`.hover`로 레일·칩·탭·버튼이 밝아진다), 누르면 실행, 오른쪽 버튼 = 이전(메뉴 장면에서만).
  게임패드 LB/RB = 레일 이전/다음(홈에서는 커서만, `[rail-shoulder]`), LT/RT = 캐릭터 이전/다음(`[char-shoulder]`, 캐릭터 화면만. 스킬 단축키 대기에서는
  RT가 원본 3번이라 띠가 표시를 거둔다), 그 밖의 화면의 LT/RT는 쪽 넘김. 이 때문에 패드에서 못 누르게 된 원본 0(장비 해제, 핫슬롯 지우기)은
  그 상태에서 RS(원본 9, 그 화면이 안 쓰는 키)로 받고 버튼 띠에 `RS`로 적는다(패드일 때만 별칭). RB의 7(장비 상세설명)은 설명이 늘 보여 길을 두지 않았다.
  키보드 Tab/Shift+Tab = 레일 다음/이전(틀이 떠 있을 때만, 그동안 왼쪽 Shift는 뗄 때 LSK로 보내고 Tab을 눌렀으면 보내지 않는다), `[` `]` = 캐릭터.
  장비 칸 상태의 ←→는 원본대로 캐릭터 넘김이고(후보로는 OK·「후보」·후보 줄·고른 칸 다시 누르기로만 간다, 사용자 결정 2026-11-11), 후보에서 ←는 칸으로. 스킬 목록의 ←→는 분류 탭.
  아이템 목록·핫슬롯 등록은 줄을 누르면 고르기만 하고, 사용 대상 단계·등록은 「사용」/「등록」, OK, 고른 줄 다시 누르기로 간다.
- 시험: `nctl.sh`의 `mclick <x> <y>`(마우스 왼쪽, 조작 장치는 키보드 그대로), `rclick <x> <y>`(오른쪽), `scan shift+Tab`, `scan ']'`.

## RmlUi에서 주의할 점

- 기본 스타일시트가 없다. `div`는 base.rcss가 block으로 잡아 준다. **flex 컨테이너의 직계 글은 보이지 않으니 `<span>`으로 감싼다.**
- `data-for` 안의 식에서 바깥 값은 `d.cursor`처럼 그대로 쓴다. 줄 번호는 `it_index`.
- `data-if`는 `display`를 바꾼다. 같은 요소에 `data-for`와 함께 쓰지 말고 안쪽 요소에 둔다.
- 그림자, 필터, `linear-gradient()`는 안 된다. `decorator: horizontal-gradient(#a #b)`/`vertical-gradient`, `border-radius`, `opacity`, `transform`, `transition`, `@keyframes`는 된다.
- `<img data-attr-src="it.icon"/>`는 그림 1px이 1dp로 나온다. 값이 빈 글이면 `data-if="it.icon != ''"`로 감춘다.
- 오류는 실행 로그(`<폴더>/out.log`)에 `[rml 0~2]`로 나온다. 경고가 없어야 한다.

## 빌드와 시험

자기 빌드 폴더를 쓴다(다른 작업과 겹치지 않게). 처음에 `cp -R native/build native/b_<영역>`으로 미리 빌드된 것을 복사한 뒤 `cd native && make -j8 B=b_<영역> ONLY=<영역>`. 복사한 폴더의 `list.txt`, `tr.c`, `tr.o`는 지난 목록으로 만든 것이라 지우고 빌드한다(그대로 두면 링크가 깨진다). `ONLY`는 `restored/ui_<영역>*.c`와 `restored/list.d/<영역>.txt`만 넣는다(다른 영역의 미완성 파일에 막히지 않는다). `native/build`는 건드리지 않는다. 끝나면 자기 빌드 폴더는 지운다. 문서만 고쳤으면 다시 빌드하지 않아도 된다(`ECPE_UI_DIR`).

```bash
export ECPE_HEADLESS=1 ECPE_BIN=$PWD/native/b_<영역>/ecpe ECPE_UI_DIR=$PWD/native/ui
work/tools/tofield.sh work/ui/run/<영역> --width 568 --scale 3   # 저장 사본으로 필드까지(창·소리 없음)
work/tools/nctl.sh work/ui/run/<영역> clear wait0.8 wshot menu     # 키 → 합친 화면(게임+UI) work/ui/run/<영역>/menu.png
work/tools/nctl.sh work/ui/run/<영역> classic wshot menu_orig modern   # 원작 그리기와 견주기
work/tools/nctl.sh work/ui/run/<영역> uireload wshot menu2          # rml/rcss 고친 뒤 다시 읽기
work/tools/nctl.sh stop work/ui/run/<영역>
```

- `shot <이름>`은 게임 화면만(UI 없음, 원본이 그린 것 확인용), `wshot <이름>`은 합친 화면이다. **만든 화면은 반드시 `wshot`을 직접 열어 눈으로 확인한다**(글 잘림, 겹침, 빈 값, 선택 줄 위치, 스크롤).
- `poke8|poke16|poke32 <게스트 주소 hex> <값>`으로 메모리를 바꿔 긴 목록, 파티 3명, 큰 수치 같은 경우를 만든다. `memdump <파일>`로 값을 확인한다.
- `ECPE_UI_DEMO=<문서>`로 띄우면 그 문서를 값 없이 늘 보인다(배치 확인).
- 폭은 `--width 240|320|568|640`, 배율은 `--scale`(창 화소 = 게임 화소 × 배율).
- 사용자 저장(`~/Library/Application Support/ecpe/save`)은 읽기만 하고 항상 사본으로 시험한다(tofield.sh가 복사한다).
- 조사 결과: `work/ui/survey/*.md`(화면별 그리기 함수, 상태 구조, 원본 배치), 도구: `work/ui/README.md`.

## 정해진 것

- 환경설정의 퀵모드(그리기 영역을 384×240으로 줄이는 원작 옵션)는 버린다. 새 UI에 항목을 두지 않고, 새 UI는 늘 전체 화면에 그린다.
- 필드 메뉴 틀(레일·캐릭터 띠·버튼 띠·「이전」 규칙)은 `restored/fm_shell.c`가 맡는다(영역 공용, 위 '필드 메뉴 틀').
- 필드 메뉴 분배 함수 `0x2faa4`와 그 안의 창 바탕(`0x1415c`)은 `ui_fmcore.c`(영역 fmcore)가 맡는다. 다른 영역은 자기 화면의 그리기 함수만 감싼다. 자기 빌드(ONLY)에서는 원본 바탕 상자가 뒤에 남아 보일 수 있는데, 전체 빌드에서는 사라진다.
- 여러 화면이 같이 쓰는 원본 함수는 한 영역만 감싼다(같은 오프셋을 두 영역이 list.d에 적으면 빌드가 깨진다). 자기 몫이 아닌 공용 창이 자기 화면 위에 뜨면 그대로 둔다.
